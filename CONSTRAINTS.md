# Constraints

Durable MUST / MUST NOT rules. Each has a short reason. Add a rule only when it is real and not already covered by `AGENTS.md` or `ARCHITECTURE.md`.

## Data And Migrations

- The schema MUST change only through Alembic revisions in `src/ideology_app/migrations/versions/`. Never call `Base.metadata.create_all` outside throwaway experiments. Reason: one migration history for SQLite (dev) and PostgreSQL (target).
- Autogenerated revisions MUST be reviewed by hand before they are kept. Reason: autogenerate emits each non-native Enum CHECK three times (the Enum's own plus two explicit `sa.CheckConstraint`s), which gives duplicate constraint names on PostgreSQL; delete the explicit `sa.CheckConstraint` lines and confirm `alembic check` reports no drift.
- DDL and queries MUST stay portable to PostgreSQL: no SQLite-only types, functions or SQL. Enums MUST be non-native (`native_enum=False, create_constraint=True`) with exactly one CHECK each. Reason: SQLite is only the dev default.
- Every Engine that is created MUST be disposed (`finally: engine.dispose()` or `ctx.call_on_close`). Reason: on Python 3.15 an undisposed SQLite engine emits `ResourceWarning: unclosed database`, which fails the pytest gate (`filterwarnings = ["error"]`).
- A migration MUST NOT recreate (batch copy-and-move) a SQLite table that other tables reference with `ON DELETE CASCADE`: migrations run with `PRAGMA foreign_keys=ON`, so dropping the old table deletes every child row. Use plain `ADD COLUMN` / `DROP COLUMN` (`op.batch_alter_table(..., recreate='never')`; SQLite ≥ 3.35) as `0008` does, and test the downgrade with child rows. Reason: a downgrade of `pipeline_runs` that recreated the table deleted every Dataset Version in testing; `0003`'s downgrade already loses `source_document_pages` this way (see `docs/risks-and-open-questions.md`).
- Tests MUST use a temporary SQLite database (the `db_url` / `migrated_engine` fixtures, or `--database-url` for the CLI) and MUST NOT touch `./ideology.db`. Reason: the default URL is relative to the current directory; `tests/conftest.py` unsets `DATABASE_URL` and changes into `tmp_path` for every test as a safety net.

## Source Documents

- Only `src/ideology_app/pdf_text.py` MAY import `pypdf` in application code. Reason: one adapter to swap or harden the PDF library; tests may use pypdf only to build fixtures (`tests/pdf_factory.py`).
- Stored Source Document files MUST be content-addressed (`<SOURCE_FILES_DIR>/<sha256>.pdf`) and MUST NOT be overwritten, edited or renamed. Reason: the content hash identifies the exact bytes that Evidence quotes come from, and several rows may share one file.
- Page text MUST be stored as extracted (only NUL characters removed). Any whitespace/accent normalisation for quote matching MUST happen at match time. Reason: Evidence must stay verifiable against the original extraction.
- Tests MUST build PDFs with `tests/pdf_factory.py` (no committed binaries, no network) and MUST point `SOURCE_FILES_DIR` / `files_dir` into `tmp_path`, never `./source_files`. Reason: the default directory is relative to the current directory.

- Only `src/ideology_app/http_fetch.py` MAY fetch Source Document URLs (`urllib.request` / `http.client`), and it MUST allow only `http`/`https`, including after redirects (no `file:`, `ftp:` or `data:` handler). Reason: one place to harden downloads, and an Operator-typed URL must not read local files.
- Every caught `urllib.error.HTTPError` MUST be closed. Reason: on Python 3.15 an unclosed `HTTPError` emits `ResourceWarning: Implicitly cleaning up`, even with `fp=None`, which fails the gate; test fakes build it with `io.BytesIO(b"")` (`tests/http_fakes.py`).
- Tests MUST NOT open a network connection: mock `ideology_app.http_fetch._open` (or pass `fetch=` to `add_url_document`) and keep the autouse socket guard in every module that touches URL fetching. Reason: a deterministic, offline CI.

## LLM Providers

- Only `ideology_app.llm.*_provider` modules MAY import a vendor LLM SDK (e.g. `anthropic`); tests of that adapter are the only other exception. Everything else gets a provider through `build_provider` or by injection. Reason: the provider is configuration, not code branches.
- Tests MUST NOT need or read a real API key and MUST NOT open a network connection. Use `FakeProvider`, or inject an SDK client backed by `httpx2.MockTransport`, and keep the autouse env/socket guard in every LLM test module. Reason: the AGENTS.md invariant and a deterministic, offline CI.
- API keys MUST NOT appear in reprs, error messages or logs; error messages from provider failures carry only the exception class name and HTTP status. Reason: keys leak through tracebacks and Pipeline Run records.
- An `AnthropicProvider` that creates its own client MUST be closed (`with provider:` or `close()`). Reason: an unclosed HTTP client can emit a `ResourceWarning`, which fails the gate.

## Pipeline

- Any change to a prompt's system text, template or output schema in `src/ideology_app/pipeline/prompts.py` MUST bump that prompt's `version` and its fingerprint in `tests/test_pipeline_prompts.py`. Reason: each Pipeline Run records `prompt_versions`, which must identify the prompt actually used.
- The pipeline MUST NOT send Party names or short names to the LLM in any prompt (Statements or Party Positions; only page text, Statement texts and ids reach `generation.py` and `positions.py`). Reason: perceived bias, and the UI treats all parties identically.
- Dataset Versions, Statements, Party Positions and their Evidence MUST NOT be updated or deleted by application code (only database cascades delete them). The one exception is a Dataset Version's `status` (see the publishing rules below). Statements are stored exactly as the provider returned them; rejecting bad Statements is Validation's job. Reason: Dataset Versions are immutable and AI output is never edited by hand.
- Evidence quotes MUST be stored exactly as the LLM returned them (pages too). Any normalisation MUST happen only when matching (`validation-evidence-quotes`) or for display. Reason: Validation and Voters must see what the model actually cited.
- A Dataset Version MUST be written only together with all its Statements and Party Positions, in one transaction (`runs._finish`). Reason: a partial Dataset Version could be validated or published without positions.
- `ideology_app.pipeline` MUST depend on the `LLMProvider` protocol (`llm.base`), never on a concrete provider or `build_provider`; the CLI resolves the provider in `cli._provider`. Reason: the provider is configuration, and tests inject `FakeProvider`.

## Validation

- Validation checks MUST be pure functions of `ValidationInput` (no database, LLM, network or clock). Reason: checks are unit-tested on plain data and give the same result on every re-run; anything a check needs is loaded once in `validation.base.load_input`.
- Validation results and report entries MUST be written only by `pipeline.runs.validate_run`, in the same commit as the run's `passed` / `failed` status, and MUST NOT be updated or deleted. Reason: the report is the durable record of why a run passed or failed.
- Evidence quote matching and Statement duplicate detection MUST go through `validation.evidence_quotes.normalize_for_match`. Reason: one matching rule for Validation and anything later that shows whether a quote was found.
- Validation thresholds MUST come from `config.ValidationSettings` (read from the environment by `config.validation_settings()` and passed into `ValidationInput.settings`), never from literals inside a check. Reason: thresholds are configuration, and checks stay pure and testable at any threshold.
- A Party below the coverage threshold MUST fail the whole run and MUST NOT be excluded from a Dataset Version. Reason: excluding a Party silently changes the Voter's ballot, the UI treats all Parties identically, and AI output is never edited.
- A Statement that does not separate the Parties (fewer than two different values among its stances) MUST fail the whole run and MUST NOT be dropped from the Dataset Version. Reason: Dataset Versions are immutable, AI output is never edited, and the run is the unit of publication.
- A Statement set whose count is outside the configured range, that contains duplicate Statements (same text after `normalize_for_match`), or that puts more than the configured share on one topic MUST fail the whole run; Statements MUST NOT be dropped, deduplicated or reordered to make it pass. Reason: the same as for separation; the operator re-runs or changes a threshold deliberately instead.
- A Dataset Version's status (and an Election's `draft` → `active`) MUST change only in `pipeline.publishing.publish_dataset_version`, called from `validate_run`'s `passed` path in the same commit as the Validation results; checks MUST NOT change it. The only transitions are `candidate → published` and `published → superseded`; a version that is not `candidate` is never published again. Reason: publishing and superseding are one transition with its own rules (at most one Published version per Election, publish order = Pipeline Run id).
- The partial unique index `uq_dataset_versions_published_election_id` (`dataset_versions (election_id) WHERE status = 'published'`, migration `0007`) MUST NOT be dropped, and any future batch migration of `dataset_versions` MUST keep it with its WHERE clause (autogenerate and `alembic check` do not compare the WHERE clause; `tests/test_migrations.py` checks `sqlite_master`). Reason: it is the database backstop for one Published version per Election.
- When superseding, the old Published version MUST be flushed as `superseded` before the new one is set `published`. Reason: the unit of work orders UPDATEs by primary key, so a single flush can hit the partial index.
- `pipeline_runs.validation_settings` MUST be written only by `pipeline.runs.validate_run`, in the commit that stores the run's Validation results (on `passed` and `failed`), and MUST NOT be updated afterwards. Reason: it is the record of the thresholds that produced those results; a later change would make the report lie.
- `ideology pipeline report` (`pipeline.reports`) MUST stay read-only: no writes, no options that change state. Reason: AI output is never edited by hand, and the report is an observability view.

## Public API

- `/api/` routes MUST be `GET`-only and read-only (SELECT only; the request Session is never committed) and MUST NOT accept Answers (no query or body parameters). Reason: voter answers never reach the server, and the API is a public read surface.
- The API MUST NOT serve `candidate` Dataset Versions; an unknown and a `candidate` id MUST get the same `404 dataset_version_not_found`. Reason: only versions that passed Validation are published.
- A `DatasetVersion` response body MUST NOT contain mutable fields (status, the Published pointer). Reason: it is cached `public, max-age=86400, immutable`; the pointer lives in `Election.published_dataset_version_id`.
- A Party Position's `value` MUST come from `PartyPosition.engine_value`. Reason: one mapping to what the `packages/core` match-score engine consumes.
- `/api/v1` changes MUST be additive; a breaking change needs `/api/v2`. Reason: clients and old Share Links depend on the contract.

## Client-side Matching

- The Match Score MUST be computed only by `packages/core/src/domain/match-score.ts` in the client. The server MUST NOT get an endpoint that receives Answers. Reason: the invariant that voter answers are never stored or sent to the server.
- `packages/core` MUST NOT import React, DOM or platform APIs, and `match-score.ts` MUST have no imports and use no globals beyond the language built-ins. Reason: the core is shared by the web and (later) mobile clients and tested under Node.
- Client code MUST NOT put Answers in any request (path, query string, body or headers); only the URL fragment carries them (Share Links). Reason: the invariant above, and server access logs record full request lines.
- Client code MUST reach the public API only through the `packages/core` client (`createPublicApiClient`); components MUST NOT call `fetch` (only `apps/web/src/main.tsx` passes the browser `fetch` in). Reason: one place that checks the API contract and maps keys, and one place to audit that no request carries Answers.
- Web tests MUST NOT reach the network: `apps/web/src/test/setup.ts` stubs global `fetch` to throw, and tests inject a mocked `FetchLike`. Reason: a deterministic, offline CI.
- npm dependencies MUST be exact-pinned and installed with `npm ci` from the committed `package-lock.json`; any new runtime dependency MUST be justified in its feature spec. Reason: a reproducible verification gate and a small client.

## Web Client Serving

- New server routes MUST be registered in `create_app` before `web_router`, and the SPA fallback MUST NOT serve `/api/` or `/health` paths. Reason: the catch-all `GET /{path:path}` matches every path, so anything included after it is unreachable, and unknown API paths must keep their JSON `404`.
- Client route segments MUST NOT contain a `.`. Reason: the SPA fallback answers a missing path whose last segment has a `.` with `404`, so such a route would break on deep links and reloads.
