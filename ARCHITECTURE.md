# Architecture

Current state after `db-schema-elections-parties`, `llm-provider-abstraction`, `source-document-upload`, `source-document-url`, `match-score-engine`, `pipeline-generate-statements`, `pipeline-extract-positions`, `validation-evidence-quotes`, `validation-party-coverage`, `validation-statement-separation`, `validation-questionnaire-shape` and `auto-publish-dataset-version`. Keep this short; update it when layers, runtime surfaces or boundaries change.

## Layout

- Python package in src layout: `src/ideology_app/`, installed editable via `pip install -e '.[dev]'` (`pyproject.toml`, setuptools backend, `requires-python >=3.12`).
- Domain, pipeline and adapter modules will live under `src/ideology_app/` as features add them.
- Tests live in `tests/` and run with pytest (`[tool.pytest.ini_options]` in `pyproject.toml`).

## Data Layer

- Dependency direction: `config` → `db` → `models` → `elections` / `source_documents` / `validation` / `pipeline` (services; `source_documents` also uses `pdf_text` and `http_fetch`; `pipeline` also uses `llm.base` and `validation`) → `cli`. The FastAPI app does not touch the database yet.
- `ideology_app.config.database_url()`: `$DATABASE_URL`, else `sqlite:///ideology.db` (relative to the current directory; `*.db` is git-ignored). SQLite is the dev default; PostgreSQL is the target.
- `ideology_app.config.source_files_dir()`: `$SOURCE_FILES_DIR`, else `source_files/` relative to the current directory (git-ignored). Uploaded and downloaded Source Document files are stored there content-addressed as `<content_hash>.pdf` (lowercase hex SHA-256), written via a temp file + `os.replace`, never overwritten; Source Documents of different Parties with the same bytes share one file. Local disk only (no object storage yet).
- `ideology_app.db`: `make_engine(url)` (SQLite gets `PRAGMA foreign_keys=ON`), `session_scope(engine)` (commit/rollback), `alembic_config(url)`, `run_migrations(url, revision="head")`, `downgrade(url, revision)`, `is_initialised(engine)` (true only when the database's Alembic revision equals the script head, so any older schema counts as not initialised). Callers own and dispose every Engine.
- `ideology_app.models`: `Base` with a constraint naming convention (`pk_`, `fk_`, `uq_<table>_<col>_<col>`, `ck_<table>_<name>`, `ix_`); `Election` (`elections`: country, type, date, name, status; unique country+type+date) and `Party` (`parties`: election_id FK cascade, name, short_name; unique per Election). `SourceDocument` (`source_documents`: party_id FK cascade + index, origin `upload`/`url`, status `registered`/`fetched`/`parsed`/`failed`, original_filename, source_url (≤ 2048; CHECK `source_url_matches_origin`: set exactly when origin is `url`, added by hand in `0003`), content_hash, page_count, failure_reason, created_at; unique party_id+content_hash) and `SourceDocumentPage` (`source_document_pages`: source_document_id FK cascade, page_number ≥ 1, text; unique per document). `PipelineRun` (`pipeline_runs`: election_id FK cascade + index, status `queued`/`running`/`validating`/`passed`/`failed` (full domain lifecycle; a run that failed Validation keeps its `candidate` Dataset Version), llm_provider, llm_model, generation_mode (`config.GenerationMode`), prompt_versions (JSON task → version), llm_calls, input_tokens, output_tokens (default 0), failure_reason (≤ 500), created_at, started_at, generation_finished_at, validation_settings (nullable JSON, added by migration `0008`: the `ValidationSettings` fields the run was validated with, written only by `validate_run`; null before Validation and for runs validated before `0008`)), `DatasetVersion` (`dataset_versions`: election_id FK cascade + index, pipeline_run_id FK cascade and unique, status `candidate`/`published`/`superseded` (default `candidate`), created_at; `statements` ordered by position; partial unique index `uq_dataset_versions_published_election_id` on election_id `WHERE status = 'published'` (SQLite and PostgreSQL; explicit name, outside the `ix_` convention), added by migration `0007`, so an Election has at most one Published version) and `Statement` (`statements`: dataset_version_id FK cascade, position ≥ 1 (CHECK `position_positive`), text ≤ 300, topic ≤ 50 (a plain string; the topic list is versioned with the prompts); unique dataset_version_id+position), created by migration `0004`. `PipelineRunSourceDocument` (`pipeline_run_source_documents`: composite PK pipeline_run_id FK cascade + source_document_id FK cascade, role `main`/`additional`; the parsed documents a run read; relationship `PipelineRun.source_documents`) and `PartyPosition` (`party_positions`: statement_id FK cascade, party_id FK cascade + index, value (nullable integer; null = `no stance`; CHECK `value_range` −2..+2), Evidence as columns: evidence_source_document_id FK cascade, evidence_quote (text, exactly as the LLM returned it), evidence_page (CHECK `evidence_page_positive` ≥ 1), evidence_url (≤ 2048, the document's `source_url` for URL documents); CHECK `evidence_matches_value`: a null value has all four evidence columns null, a non-null value has document, quote and page; unique statement_id+party_id; `Statement.party_positions` ordered by party_id), created by migration `0005`. `ValidationResult` (`validation_results`: pipeline_run_id FK cascade + index, check_name ≤ 50 (`check` is an SQL reserved word), passed (Boolean, no CHECK), created_at; unique pipeline_run_id+check_name; `PipelineRun.validation_results` ordered by id, `passive_deletes`) and `ValidationReportEntry` (`validation_report_entries`: validation_result_id FK cascade + index, statement_id (nullable FK cascade), party_id (nullable FK cascade), message ≤ 500; `ValidationResult.entries` ordered by id), created by migration `0006`; both are insert-only. `PartyPosition.engine_value` (−2..+2 or `NO_STANCE = "no_stance"`) is the single mapping to what `match-score.js` consumes. Enums (`ElectionType`, `ElectionStatus`, `SourceDocumentOrigin`, `SourceDocumentStatus`, `PipelineRunStatus`, `GenerationMode`, `DatasetVersionStatus`, `SourceDocumentRole`) are non-native strings with one CHECK each.
- `ideology_app.elections`: plain functions taking a `Session` (`create_election`, `add_party`, `list_elections`, `list_parties`) that validate input and raise `InvalidInputError` / `NotFoundError` / `DuplicateError` (all `ElectionsError`). Duplicates are detected from `IntegrityError` on flush.
- `ideology_app.pdf_text`: the PDF adapter and the only module that imports `pypdf`. `extract_pages(bytes) -> list[str]` (one string per page, NUL removed, empty pages kept as `""`) or `PdfTextError(reason, page_count)` with reasons `PDF is encrypted`, `could not read PDF: <Exc>: <msg>` (≤ 500 chars), `PDF has no pages`, `no text layer found (scanned PDF?); OCR is not supported`.
- `ideology_app.http_fetch`: the HTTP adapter and the only module that does HTTP for Source Documents (stdlib `urllib`). `_OPENER` has only the Proxy, Unknown, HTTP, HTTPS, HTTPDefaultError, HTTPRedirect and HTTPErrorProcessor handlers, so `file:`/`ftp:`/`data:` (and redirects to them) fail. `_open(request, timeout)` is the single test seam. `fetch_url(url, *, max_bytes)` requests an ASCII-safe form of the URL (`_ascii_url`: non-ASCII characters in the path, query and fragment are UTF-8 percent-encoded, every ASCII character including existing `%XX` escapes is kept, a non-ASCII hostname is IDNA-encoded; callers still store the URL as given), sends `User-Agent: ideology-app/0.1 (+manifesto fetch)`, uses a 60 s timeout, rejects a `Content-Length` over `max_bytes`, reads in 1 MiB chunks up to `max_bytes`, and raises `FetchError(reason)` (≤ 500 chars): `HTTP <code>: <reason>` (the `HTTPError` is closed), `could not fetch URL: <detail>` (also for any `ValueError` such as `UnicodeError` or `http.client.InvalidURL`, so no urllib/http.client error escapes), `response is empty`, `response is too large (more than N bytes)`. No retries.
- `ideology_app.source_documents`: `add_uploaded_document(session, party_id, file_path, files_dir)` validates (Party exists, regular file, 0 < size ≤ 50 MiB, starts with `%PDF-`), inserts the row (`registered`; duplicate party+hash → `DuplicateError`), then `_store_and_parse` stores the file (`fetched`) and extracts pages (`parsed` + page rows, or `failed` + `failure_reason`). `add_url_document(session, party_id, url, files_dir, fetch=None)` checks the Party and the URL (absolute http/https with a host, no credentials, whitespace or control characters, ≤ 2048 chars; `invalid URL …` otherwise) before fetching, downloads once (cap `MAX_UPLOAD_BYTES`), and on a fetch error or a body not starting with `%PDF-` returns a `failed` row with `source_url` and `failure_reason` but no hash or file; otherwise it inserts the row with `source_url` and `original_filename` (percent-decoded last path segment) and runs the same `_store_and_parse`. Rows are never re-fetched. `list_documents`, `get_document`. Reuses the `elections` error classes.
- Migrations: Alembic in `src/ideology_app/migrations/` (`script_location = ideology_app:migrations` in code; root `alembic.ini` for developer commands). `env.py` reads the URL from the config or `database_url()`, supports offline `--sql`, uses `render_as_batch=True`, and disposes its engine.
- A CHECK added to an existing table is not detected by autogenerate; write it by hand inside `op.batch_alter_table` (as `0003` does).
- Add a migration: change `models.py`, then `DATABASE_URL=sqlite:///<scratch>/gen.db .venv/bin/alembic -c alembic.ini upgrade head` and `... revision --autogenerate --rev-id 000N -m "..."`, review the file by hand (see `CONSTRAINTS.md`), and check `... alembic -c alembic.ini check` reports no drift. `tests/test_migrations.py` checks upgrade/downgrade, drift and the offline PostgreSQL render.

## LLM Providers

- Package `src/ideology_app/llm/`: `base.py` (`LLMRequest[T]` with `task`, `system`, `prompt`, `schema` (a pydantic model), `max_tokens=4096`; `LLMResult[T]` with `output`, `provider`, `model`, `input_tokens`, `output_tokens`; the `LLMProvider` protocol with `name`, `model`, `generate(request) -> LLMResult`; errors `LLMError` > `LLMConfigError` (also a `config.ConfigError`), `LLMOutputError`, `LLMProviderError`), `fake.py` (`FakeProvider`), `anthropic_provider.py` (`AnthropicProvider`), `__init__.py` (re-exports, `PROVIDERS` registry, `build_provider`).
- Selection: `build_provider(llm_settings())`. `PROVIDERS` / `build_provider` is the only place that branches on the provider name. Callers depend on the `LLMProvider` protocol, never on a concrete class.
- Configuration (`ideology_app.config`): `LLM_PROVIDER` (`anthropic` default, or `fake`), `LLM_MODEL` (default per provider from `DEFAULT_MODELS`: `anthropic` -> `claude-sonnet-5-5`, `fake` -> `fake-model`), `GENERATION_MODE` (`GenerationMode.PRECOMPUTED` default, or `LIVE`; parsed only, no behaviour yet). Values are trimmed, case-insensitive, and blank means unset. Invalid values raise `ConfigError` (a `ValueError`) listing the supported values. `VALIDATION_MIN_PARTY_COVERAGE_PERCENT` (ASCII digits only, 0..100, default `DEFAULT_MIN_PARTY_COVERAGE_PERCENT = 70`; trimmed, blank = unset; anything else raises `ConfigError` `Invalid VALIDATION_MIN_PARTY_COVERAGE_PERCENT '<raw>'; expected an integer from 0 to 100`) , `VALIDATION_MIN_STATEMENTS` / `VALIDATION_MAX_STATEMENTS` (ASCII digits only, at least 1, defaults `DEFAULT_MIN_STATEMENTS = 25` / `DEFAULT_MAX_STATEMENTS = 35`; else `Invalid VALIDATION_MIN_STATEMENTS '<raw>'; expected a positive integer`; a min above the max, defaults included, raises `Invalid statement count range: VALIDATION_MIN_STATEMENTS (<min>) is greater than VALIDATION_MAX_STATEMENTS (<max>)`) and `VALIDATION_MAX_TOPIC_SHARE_PERCENT` (0..100, default `DEFAULT_MAX_TOPIC_SHARE_PERCENT = 30`, same message shape as the coverage variable) are read by `validation_settings() -> ValidationSettings` (see Validation), checked in the order coverage, min, max, range, share; the first error wins. `ANTHROPIC_API_KEY` is read only by `AnthropicProvider`, lazily on the first `generate`.
- `FakeProvider(responses, model="fake-model")`: canned responses keyed by `task` (dict, schema instance, or callable `(request) -> dict | model`), validated against the schema; records `calls`; deterministic word-count token numbers. Unknown task -> `LLMError`; schema mismatch -> `LLMOutputError`.
- `AnthropicProvider(model, *, client=None, api_key=None, max_retries=2, timeout=120.0)`: `client.messages.parse(..., output_format=request.schema)` (SDK structured output, `output_config.format.type == "json_schema"`). Maps `pydantic.ValidationError`, refusals and missing parsed output to `LLMOutputError`, and `anthropic.APIError` to `LLMProviderError` (class name and HTTP status only). Closes only a client it created (`close()` / `with`). Retries are the SDK's `max_retries`.
- Dependency direction: `config` -> `llm`. `config` never imports `llm`. `pipeline` imports only `llm.base`; `cli` imports `build_provider` (in `cli._provider`).
- Add a provider: write `src/ideology_app/llm/<name>_provider.py` implementing the protocol, add one entry to `PROVIDERS` and one to `config.DEFAULT_MODELS`.
- Tests: `tests/test_llm.py` (config, registry, fake) and `tests/test_llm_anthropic.py` (adapter through an injected `anthropic.Anthropic` with an `httpx2.MockTransport` `http_client`). Each has an autouse guard that unsets the LLM env vars and blocks `socket.socket.connect` / `socket.create_connection`.

## Pipeline

- Package `src/ideology_app/pipeline/`: `prompts.py` (topics, schemas, versioned prompts), `generation.py` (chunking and Statement LLM calls, no database), `positions.py` (Party Position LLM calls, no database), `runs.py` (Pipeline Run service), `publishing.py` (publish and supersede Dataset Versions), `reports.py` (read-only Pipeline Run report), `__init__.py` (re-exports). Dependency direction: `models` / `elections` (errors) / `llm.base` → `pipeline` → `cli`. It never imports a concrete provider; the provider is injected.
- `prompts.py`: `Topic` (a `Literal` of 18 slugs, `economy` … `infrastructure_transport`) and `TOPICS`; schemas `StatementDraft` (`text` 1..300 chars with a non-space character, `topic: Topic`), `CandidateList` (`candidates`, ≤ 12), `StatementSet` (`statements`, 1..60); `PromptSpec(task, version, system, template, schema, max_tokens)` with `STATEMENT_CANDIDATES` (`v1`, 4096 tokens, field `{chunk}`) and `GENERATE_STATEMENTS` (`v1`, 8192 tokens, fields `{candidates}`, `{count}`); `POSITION_FINDINGS` (`position_findings`, `v1`, 4096 tokens, fields `{statements}`, `{chunk}`; schema `FindingList(findings ≤ 60 of Finding(statement ≥ 1, value −2..+2, quote 1..500 chars with a non-space, page ≥ 1))`) and `PARTY_POSITIONS` (`party_positions`, `v1`, 8192 tokens, fields `{statements}`, `{candidates}`; schema `PositionList(positions ≤ 60 of PositionChoice(statement ≥ 1, value −2..+2, evidence ≥ 1))`); `PROMPT_VERSIONS` (task → version for all four tasks, recorded on every run); `TARGET_STATEMENT_COUNT = 30`. Prompts are in Spanish and state the single-proposition, neutral-wording, 5-point-scale and topic rules; the reduce prompt adds topic spread (no topic over about a quarter), no near-duplicates and the target count.
- `generation.py`: `CHUNK_MAX_CHARS = 40_000`, `MAX_LLM_CALLS_PER_RUN = 200`. `build_document_chunks(documents)` returns `Chunk(party_id, document_id, text)`; `build_chunks(documents)` is its texts (pure; `DocumentPages(party_id, document_id, pages, source_url=None, role=main)`): documents ordered by Party id then document id, pages by number; each page rendered as `[página N]\n<text as stored>`, pages joined by a blank line; a chunk holds whole consecutive pages of one document and is at most the limit (a page over the limit is cut into consecutive slices, each under its marker); whitespace-only pages are left out. `generate_statements(provider, chunks, usage)`: map (one `statement_candidates` call per chunk), then reduce (candidates with exact duplicates removed, sorted by (topic, text), one `generate_statements` call). `Usage` (calls, input/output tokens) is updated after each successful call. `GenerationError` for `too many chunks: <n> (limit 199)` (before any call) and `no statement candidates were found in the source documents`; `LLMError` propagates.
- `positions.py`: `MAX_POSITION_CALLS_PER_RUN = 300`; `plan_position_calls(documents)` = chunks + Parties with at least one chunk (an upper bound). `extract_positions(provider, statements, documents, party_ids, usage)`: Parties in id order; each chunk of a Party's documents (main document first, then document id, then page; the same 40,000-character chunks) gets one `position_findings` call whose prompt lists the Statements as `[n] <text>` and then the chunk; findings become numbered candidates `C<k> [programa principal|programa adicional] [afirmación n] [valor v] [página p] «quote»`, and one `party_positions` call per Party picks one stance per Statement and the candidate it cites (any candidate for any Statement). No candidates → no reduce call. Returns exactly n `PositionResult(statement_number, value, document_id, quote, page, url)` per Party; omitted Statements and Parties without documents are `no stance`. `GenerationError` for `position_findings|party_positions referred to unknown statement <n>`, `party_positions repeated statement <n>` and `party_positions referred to unknown evidence candidate <k> (…)`; `LLMError` propagates. Quotes and pages are kept as returned (no Validation here). Coalition precedence is a prompt rule: the main (joint) manifesto wins on conflict.
- `runs.py`: `queue_run(session, election_id, *, llm_provider, llm_model, generation_mode)` (Election must exist and have a `parsed` Source Document; flushes a `queued` run; the caller commits). `execute_run(engine, run_id, provider, validation_settings=None) -> RunOutcome` first resolves `validation_settings` (`None` → `config.validation_settings()`, so an invalid value raises `ConfigError` before any write or LLM call), then commits at two points: (1) checks the run is `queued` and the provider's `name`/`model` equal the recorded ones (else `InvalidInputError`, nothing changed), records a `pipeline_run_source_documents` row per parsed document (each Party's lowest-id parsed document is `main`, the others `additional`), sets `running` + `started_at` and loads the parsed pages (with `source_url` and role) and the Election's Party ids as plain data; then, outside any transaction, checks the position call budget (`too many position extraction calls: <n> (limit 300)`, before any LLM call), generates the Statements and extracts the positions; (2) in one commit inserts a `candidate` `DatasetVersion`, its Statements at positions 1..n exactly as returned and n × Parties `PartyPosition` rows, and sets `validating`, then (3) calls `validate_run(..., settings=validation_settings)` outside its own `try` and returns that outcome (see Validation); or on `LLMError` / `GenerationError` sets `failed` with `str(exc)[:500]` and no Dataset Version; `KeyboardInterrupt` sets `failed` with `interrupted` and is re-raised; any other exception sets `failed` with `unexpected error: <ClassName>` and is re-raised. The source-document rows of a failed run remain. Both record usage and `generation_finished_at`. `RunOutcome` has `statement_count`, `position_count` and `failed_checks`. `list_runs(session, election_id)`, `get_dataset_version(session, id)`, `list_positions(session, dataset_version_id, party_id=None)` (ordered by Statement position then Party id; `NotFoundError` for an unknown version or a Party not in its Election). No update or delete path for Dataset Versions, Statements or Party Positions.
- `publishing.py` (imports `sqlalchemy` and `models` only, never commits): `PublishOutcome(election_id, published, published_dataset_version_id, published_run_id, superseded_dataset_version_id=None)` (frozen; `published_*` names the version live after the call). `election_lock_statement(election_id)` = `select(Election)…with_for_update()`. `get_published_dataset_version(session, election_id)` (`None` before the first publish). `publish_dataset_version(session, version)`: `ValueError` unless the version is `candidate`; locks the Election row; if the current Published version belongs to a run with a higher id, returns `published=False` with that version's ids and changes nothing (publish order = Pipeline Run id, i.e. queue order; Dataset Version ids follow finish order and are not used); otherwise sets the current one `superseded` and flushes **before** setting the new one `published` (the unit of work orders UPDATEs by primary key, so without that flush the partial index could see two Published rows), sets a `draft` Election `active` (`active`/`archived` stay), and flushes. Concurrency: on PostgreSQL the `FOR UPDATE` row lock serialises publishers of one Election; on SQLite (`FOR UPDATE` is dropped) `validate_run` publishes after its first write (the results flush), which holds the database write lock, so a second finisher waits (pysqlite's 5 s busy timeout) and then reads the committed Published version; the partial unique index is the backstop (`IntegrityError` → rollback).
- `reports.py` (read-only: `SELECT`s only, no write path): `get_run_report(session, run_id) -> RunReport` (`NotFoundError` for an unknown run). `RunReport` is frozen: the run's stored fields (status, failure_reason, provider, model, Generation Mode, prompt_versions, timestamps, usage, `validation_settings`), `validated_at` (`min(validation_results.created_at)`), the Dataset Version's id, status and Statement count (`None` without one), the Election's live version (`live_dataset_version_id`, `live_run_id` from `publishing.get_published_dataset_version`) and `results` (`list_validation_results`, ORM rows read inside the caller's session). Formatting is the CLI's (`pipeline report`). Dependency: `models`, `publishing`, `runs` → `reports` → `cli`.
- A successful run ends `passed` or `failed` after Validation; a `passed` run publishes its Dataset Version in the same commit (see `validate_run`). A hard kill or crash still leaves a run `running` (no recovery command); one left in `validating` is finished with `ideology pipeline validate --run N`. The CLI runs synchronously in both Generation Modes and only records the mode.
- Bump a prompt: edit `prompts.py`, change that prompt's `version` (e.g. `v2`), and replace its `(task, version)` entry in `FINGERPRINTS` in `tests/test_pipeline_prompts.py` with the fingerprint the failing test prints.
- Tests: `tests/pipeline_fixtures.py` (ORM seeding, default fake responses for all four tasks, `chunk_pages` / `candidate_lines` request parsers, `offline_guard`), `tests/test_pipeline_prompts.py`, `tests/test_pipeline_generation.py`, `tests/test_pipeline_positions.py`, `tests/test_pipeline_runs.py`, `tests/test_publishing.py`, `tests/test_cli_pipeline.py`, `tests/test_cli_pipeline_report.py`, each with the autouse env/socket guard.

## Validation

- Package `src/ideology_app/validation/`: `base.py` (data and `load_input`), `evidence_quotes.py` (check 2), `party_coverage.py` (check 3), `statement_separation.py` (check 4), `statement_uniqueness.py` (check 1, uniqueness part), `statement_count.py` (check 5), `topic_spread.py` (check 6), `__init__.py` (`CHECKS`, `run_checks`, re-exports incl. `ValidationSettings`). Dependency direction: `config` / `models` → `validation` → `pipeline.runs` → `cli`. It never imports `pipeline`, `llm` or `pdf_text`, and never reads the environment itself.
- `config.ValidationSettings(min_party_coverage_percent=70, min_statements=25, max_statements=35, max_topic_share_percent=30)`: frozen; `__post_init__` raises `ValueError` unless each value is an `int` (not `bool`): the two percents in 0..100, the two counts at least 1, and `min_statements <= max_statements`. It is how checks get thresholds: one process-wide value (no per-Election override; recorded on the run as `pipeline_runs.validation_settings` by `validate_run`), read by `config.validation_settings()` and passed explicitly: `validate_run(..., settings)` / `execute_run(..., validation_settings)` → `load_input(session, run, settings)` → `ValidationInput.settings`.
- `ValidationInput(statements, positions, party_ids, documents, settings=ValidationSettings())`: plain frozen data. `statements` are `StatementRow(id, position, text, topic)` in position order; `positions` are `PositionRow(statement_id, statement_position, party_id, value, document_id, quote, page, url)` by Statement position then Party id (`value` None = `no stance`); `party_ids` the Election's Parties in id order; `documents` maps document id → `RunDocument(party_id, role, source_url, pages: {page_number: text})` for every `pipeline_run_source_documents` row. `settings` the thresholds. `load_input(session, run, settings)` builds it and is the only database read for checks.
- `Check(name, run)`: `name` is a stable slug ≤ 50 chars; `run(ValidationInput) -> list[ReportEntry]`. `ReportEntry(message, statement_id=None, party_id=None)` (message ≤ 500; cut when stored). `CheckResult(name, entries)`, `passed = not entries`. `CHECKS: tuple[Check, ...] = (EVIDENCE_QUOTES, PARTY_COVERAGE, STATEMENT_SEPARATION, STATEMENT_UNIQUENESS, STATEMENT_COUNT, TOPIC_SPREAD)`: registry order is run order, and new checks are appended (so existing result rows and `failure_reason` strings stay stable); `run_checks(data, checks=CHECKS)` runs every check in registry order with no short-circuit.
- Checks are pure functions of `ValidationInput`: no database, LLM, network or clock.
- Add a check: write `validation/<name>.py` exporting a `Check` and append it to `CHECKS`. If it needs more run data, add a field to `ValidationInput` and fill it in `load_input`; if it needs a threshold, add a field to `config.ValidationSettings` plus its env reading in `config.validation_settings()` (never a literal in the check). Storage, the CLI and the run transition need no change.
- `pipeline.runs.validate_run(engine, run_id, checks=CHECKS, settings=None) -> RunOutcome`: `settings=None` → `config.validation_settings()`, read first, before any session (an invalid value raises `ConfigError` and changes nothing). Unknown run → `NotFoundError`; not `validating` → `InvalidInputError` (`pipeline run N is <status>, expected validating`), nothing changed. Otherwise, in one commit, inserts one `ValidationResult` per check (with its entries, in order), records `dataclasses.asdict(settings)` in `run.validation_settings` (both outcomes; never on the rollback path) and sets `passed`, or `failed` with `validation failed: <failed names, comma-separated>` (≤ 500). On `passed`, the same session then calls `publishing.publish_dataset_version` (supersede, publish, Election `draft` → `active`), so the results, the status and the publication share one commit; on `failed` the Dataset Version stays `candidate` and no status changes. `RunOutcome.publish` is the `PublishOutcome` (`None` unless `passed`). If a check or the publish step raises, the transaction rolls back (no result rows, no status change), the run is set `failed` with `unexpected error: <ClassName>` (Ctrl-C: `interrupted`) in a new session, and the exception is re-raised. `list_validation_results(session, run_id)` (check order, entries with their Statement; `NotFoundError` for an unknown run).
- `evidence_quotes` (`validation/evidence_quotes.py`): `normalize_for_match(text)` = NFKD, `casefold()`, NFKD, then keep only `isalnum()` characters that are not combining marks (accents, case, ligatures, NBSP, soft hyphens, all whitespace and punctuation fold or drop; word order and every letter and digit still count). `quote_starts_on(norm_quote, norm_pages, page)`: the quote occurs in page + next page at an index inside the cited page. For each stance (non-null value), in input order, the first failing rule becomes one entry with its `statement_id` and `party_id`: (1) the document is a run document of the same Party, else `source document D is not a source document of party P in this run`; (2) `url` equals the document's `source_url` (both null for uploads), else `evidence URL does not match source document D`; (3) the page exists, else `page P does not exist in source document D (N pages)`; (4) the normalised quote is non-empty, else `quote has no letters or digits`; (5) the quote starts on the cited page, else `quote not found on page P of source document D (found on page Q)` (first other page, in page order, where it starts) or `quote not found in source document D`. Pages are normalised lazily, once per document per check. No edit distance, no minimum length; stored quotes and page text are never changed.
- `party_coverage` (`validation/party_coverage.py`): a Party is covered on a Statement when its Party Position there is not `no stance`. With `total = len(statements)` (0 → no entries: coverage is undefined and the count is another check's job), stances are counted per Party id in `party_ids` (positions of other Party ids are ignored); a Party fails when `covered * 100 < percent * total` (integers only, so exactly the minimum passes). One entry per failing Party, in `party_ids` order, with `party_id` and no `statement_id`: `party P has positions on C of N statements (F%); minimum is T%` (`F = C * 100 // N`, floored, so always below `T`). A failing Party fails the whole run; it is never excluded.
- `statement_separation` (`validation/statement_separation.py`, no threshold): a Statement separates the Parties when its stances (non-null values of Parties in `party_ids`) hold at least two different values; `no stance` is ignored, and `0` is a stance like any other. Zero Statements → no entries (checked first). Fewer than two Parties in `party_ids` → one Election-level entry with no `statement_id` or `party_id`: `statements cannot separate parties: the election has N party|parties; at least 2 are needed`. Otherwise one entry per non-separating Statement, in `statements` order, with its `statement_id` and no `party_id`; `S` is the Statement position: `statement S does not separate parties: no party has a stance` / `...: only party P has a stance (value V)` / `...: all K parties with a stance have value V`. Positions of Party ids outside `party_ids` or of unknown Statement ids are ignored. A non-separating Statement fails the whole run; it is never dropped. When a Party has no stances, `party_coverage` reports that Party and `statement_separation` reports every Statement left with fewer than two stances: this double reporting is intended (checks stay independent; the message names the cause).
- `statement_uniqueness` (`validation/statement_uniqueness.py`, no threshold): two Statements are duplicates when their texts are equal after `evidence_quotes.normalize_for_match` (reused, so the repo has one normalisation rule: case, accents, ligatures, whitespace and punctuation are ignored; word order and every letter and digit count). Topic is ignored. One entry per later copy, in `statements` order, with its `statement_id` and no `party_id`: `statement S duplicates statement F` (`F` = the first Statement with that text). Paraphrases are not detected, and the single-proposition half of check 1 is not automated (prompts only). Separators are dropped, so `2,1 %` and `21 %` collide, and a text with no letters or digits normalises to `""`: both can only cause a false failure.
- `statement_count` (`validation/statement_count.py`): passes when `settings.min_statements <= n <= settings.max_statements` (inclusive). Otherwise one run-level entry (no ids): `questionnaire has N statements; expected MIN to MAX`. It owns the zero-Statements case (0 fails).
- `topic_spread` (`validation/topic_spread.py`): with `total = len(statements)` (0 → no entries), a topic fails when `count * 100 > settings.max_topic_share_percent * total` (strictly above; integers only). One run-level entry (no ids) per failing topic, in order of first appearance: `topic T has C of N statements (P%); maximum is M%` (`P = -(-C * 100 // N)`, the ceiling, so always above `M`).
- None of the three reads another check's result; any failure fails the whole run, and Statements are never dropped, deduplicated or reordered.
- Tests: `tests/test_validation_evidence_quotes.py` (plain data), `tests/test_validation_party_coverage.py` (plain data and config), `tests/test_validation_statement_separation.py` (plain data, registry prefix), `tests/test_validation_questionnaire_shape.py` (plain data and config for the three shape checks, full registry tuple), `tests/test_validation_runs.py` (`execute_run` / `validate_run`, stub checks), Validation CLI tests in `tests/test_cli_pipeline.py`, each with the autouse env/socket guard.

## Client-side Matching

- Module: `src/ideology_app/static/js/match-score.js`, a pure ES module (named exports only, no imports, no browser or network globals). It implements the Matching Rule in `docs/build-brief.md` and is meant to run in the Voter's browser, so Answers never reach the server. Intended URL once a UI feature mounts `/static` (not mounted yet): `/static/js/match-score.js`, loaded from a `<script type="module">`.
- Exports: `SKIP = "skip"` (Answer value), `NO_STANCE = "no_stance"` (Party Position value), `IMPORTANT_WEIGHT = 2`, `LOW_COVERAGE_THRESHOLD = 5`, `statementAgreement(a, p)` (`1 - |a - p| / 4`), `computeMatchScore(answers, positions, options)` → `{ matchScore, sharedStatementCount, lowCoverage }`, `computeMatchScores(answers, parties, options)` → the same plus `partyId`, in input order (no sorting).
- Inputs: Answers `{ statementId, value: -2..2 | "skip", important?: boolean }`, Positions `{ statementId, value: -2..2 | "no_stance" }`, Parties `{ partyId, positions }`. `statementId` is matched by `String(statementId)`. `options.lowCoverageThreshold` is a positive integer.
- Zero shared Statements gives `matchScore: null` and `lowCoverage: true` (never `NaN`). A missing Answer or Position is excluded like skip / no stance. Invalid input throws `TypeError` (non-array, non-boolean `important`) or `RangeError` (bad value, duplicate `statementId`, bad threshold) naming the field and `statementId`.
- The root `package.json` is `{"private": true, "type": "module"}` only, so Node treats the `.js` files as ES modules without a warning. It has no dependencies and is never used for `npm install`.
- Tests: `tests/js/*.test.js` with `node:test` and `node:assert/strict` (Node >= 22, built in, no npm packages).

## Verification Gate

- `./init.sh` runs from its own directory, creates `.venv` if missing (`${PYTHON:-python3} -m venv`), then runs ordered steps through `run_step <name> <function>`, which prints `==> <name>`, runs the step in a `( set -e; ... )` subshell outside any condition (bash ignores `set -e` inside `if`/`!`/`&&`/`||`), and exits 1 with `FAILED: <name> (exit N)` on failure. So any failing command in a multi-command step fails the gate.
- Current steps: `node` (Node.js >= 22 on `PATH`, `NODE_MIN_MAJOR`; fails before anything is installed), `install` (`pip install -e '.[dev]'`), `pytest`, `js-test` (`node --test tests/js/*.test.js`; fails if there are no test files, because `node --test` exits 0 when nothing matches). Pytest runs with `filterwarnings = ["error"]`, so warnings (including leaked-connection `ResourceWarning`s) fail the gate. Migration checks run inside pytest. `tests/test_init_script.py` checks `run_step` and `step_node` by extracting them from `init.sh`.
- To add a step, define a `step_<name>` function and add a `run_step` line after the existing ones. Steps are functions so their arguments are never word-split. Keep `init.sh` compatible with macOS `/bin/bash` 3.2 (under `set -u`, check an array's length before expanding `"${arr[@]}"`).
- `init.sh` never starts a server; it only prints the start command after all checks pass.
