# Architecture

Current state after `db-schema-elections-parties`, `llm-provider-abstraction`, `source-document-upload`, `source-document-url`, `match-score-engine`, `pipeline-generate-statements`, `pipeline-extract-positions`, `validation-evidence-quotes`, `validation-party-coverage`, `validation-statement-separation`, `validation-questionnaire-shape`, `auto-publish-dataset-version`, `pipeline-run-report`, `public-dataset-api`, `web-client-skeleton`, `landing-election-picker`, `questionnaire-answer-flow`, `methodology-page`, `questionnaire-important-flag`, `results-ranking`, `results-breakdown-evidence`, `share-link-create`, `share-link-open` and `llm-provider-claude-code`. Keep this short; update it when layers, runtime surfaces or boundaries change.

## Layout

- Python package in src layout: `src/ideology_app/`, installed editable via `pip install -e '.[dev]'` (`pyproject.toml`, setuptools backend, `requires-python >=3.12`).
- Domain, pipeline and adapter modules will live under `src/ideology_app/` as features add them.
- Tests live in `tests/` and run with pytest (`[tool.pytest.ini_options]` in `pyproject.toml`).
- Client code (TypeScript) lives in npm workspaces: `packages/core/` and `apps/web/` (see Web Client).

## Data Layer

- Dependency direction: `config` → `db` → `models` → `elections` / `source_documents` / `validation` / `pipeline` (services; `source_documents` also uses `pdf_text` and `http_fetch`; `bundle_import` uses `elections`, `source_documents` and `source_bundle`, which is pure (no database, no pypdf); `pipeline` also uses `llm.base` and `validation`) → `cli`. The FastAPI app reads the database only through `api` (`db` / `models` / `pipeline.publishing` → `api` → `main`).
- `ideology_app.config.database_url()`: `$DATABASE_URL`, else `sqlite:///ideology.db` (relative to the current directory; `*.db` is git-ignored except the committed shared `data/ideology.db`). SQLite is the dev default; PostgreSQL is the target.
- Shared database (`shared-database`): `config.SHARED_DATABASE_PATH` = `data/ideology.db` (relative to the current directory), committed beside the bundles (`data/ideology.db` + `data/elections/<slug>/`), selected only through `DATABASE_URL=sqlite:///data/ideology.db` / `--database-url`. `ideology_app.shared_db` (stdlib + SQLAlchemy `make_url`, depends only on `config`; never invokes git, never writes): `sqlite_path(url)` (the file of a SQLite URL, including a `file:` URI, else `None`), `is_shared(url)` (its resolved path equals `SHARED_DATABASE_PATH.resolve()`), `SIDECARS` (`-journal`, `-wal`, `-shm`), `sidecar_paths(path)`, `file_checks(path)` (sidecars, the SQLite magic, header bytes 18-19 equal 1 = rollback journal; reads 100 bytes only), `read_only_url(path)` (`sqlite:///file:<abs path, percent-encoded twice>?mode=ro&uri=true`: opening it never writes or creates a file), `MISSING_SHARED`. `.gitignore` ignores `*.db`, `*.db-journal`, `*.db-wal`, `*.db-shm` and un-ignores `data/ideology.db`; `.gitattributes` marks it `binary`. The app never sets WAL, so a file with no sidecar is complete.
- `ideology_app.config.source_files_dir()`: `$SOURCE_FILES_DIR`, else `source_files/` relative to the current directory (git-ignored). Uploaded and downloaded Source Document files are stored there content-addressed as `<content_hash>.pdf` (lowercase hex SHA-256), written via a temp file + `os.replace`, never overwritten; Source Documents of different Parties with the same bytes share one file. Local disk only (no object storage yet).
- `ideology_app.config.elections_data_dir()`: `$ELECTIONS_DATA_DIR` (trimmed), else `data/elections` relative to the current directory. It holds the committed Source Text Bundles, one per Election in `<slug>/` (`election.toml` plus the listed `.md` files only; no PDF, `.gitignore` `data/**/*.pdf`; `.gitattributes` marks `data/elections/**/*.md` `-text linguist-generated`). The 2023 bundle is `data/elections/es-general-2023-07-23/` (9 Parties, about 2.9 MB). The shared DB of `shared-database` (`data/ideology.db`) sits outside every bundle directory.
- `ideology_app.db`: `make_engine(url)` (SQLite gets `PRAGMA foreign_keys=ON`), `session_scope(engine)` (commit/rollback), `alembic_config(url)`, `run_migrations(url, revision="head")`, `downgrade(url, revision)`, `head_revision()` (the script head), `is_initialised(engine)` (true only when the database's Alembic revision equals the script head, so any older schema counts as not initialised). Callers own and dispose every Engine.
- `ideology_app.models`: `Base` with a constraint naming convention (`pk_`, `fk_`, `uq_<table>_<col>_<col>`, `ck_<table>_<name>`, `ix_`); `Election` (`elections`: country, type, date, name, status; unique country+type+date) and `Party` (`parties`: election_id FK cascade, name, short_name; unique per Election). `SourceDocument` (`source_documents`: party_id FK cascade + index, origin `upload`/`url`, status `registered`/`fetched`/`parsed`/`failed`, original_filename, source_url (≤ 2048; CHECK `source_url_matches_origin`: set exactly when origin is `url`, added by hand in `0003`), content_hash, page_count, failure_reason, created_at, replaced_by_id (nullable integer, **no FOREIGN KEY**; set by `source refetch` to the newer row of the same Party and URL, or by `data import` to the newer bundle row of the same Party, that replaces this one; null = current) and last_checked_at (nullable timezone-aware datetime; when `source refetch` last downloaded the URL, any outcome), both added by migration `0009` with `recreate='never'`; bundle_file (nullable String 255, migration `0011`, `recreate='never'`: the Source Text file a row was imported from by `data import`; null for `source add` rows; `stored_filename` is `None` for bundle rows); unique party_id+content_hash). A replaced row keeps its hash, pages and file forever (old Evidence points at it); "replaced" is a marker, not a status. Migration head: `0011`. and `SourceDocumentPage` (`source_document_pages`: source_document_id FK cascade, page_number ≥ 1, text; unique per document). `PipelineRun` (`pipeline_runs`: election_id FK cascade + index, status `queued`/`running`/`validating`/`passed`/`failed` (full domain lifecycle; a run that failed Validation keeps its `candidate` Dataset Version), llm_provider, llm_model, generation_mode (`config.GenerationMode`), prompt_versions (JSON task → version), llm_calls, input_tokens, output_tokens (default 0), failure_reason (≤ 500), created_at, started_at, generation_finished_at, validation_settings (nullable JSON, added by migration `0008`: the `ValidationSettings` fields the run was validated with, written only by `validate_run`; null before Validation and for runs validated before `0008`), statement_selection (nullable JSON, migration `0012`, `recreate='never'`: the Statement Selection report, written only by `runs._finish` with the Dataset Version; null for a run without one and for runs before `0012`)), `DatasetVersion` (`dataset_versions`: election_id FK cascade + index, pipeline_run_id FK cascade and unique, status `candidate`/`published`/`superseded` (default `candidate`), created_at; `statements` ordered by position; partial unique index `uq_dataset_versions_published_election_id` on election_id `WHERE status = 'published'` (SQLite and PostgreSQL; explicit name, outside the `ix_` convention), added by migration `0007`, so an Election has at most one Published version) and `Statement` (`statements`: dataset_version_id FK cascade, position ≥ 1 (CHECK `position_positive`), text ≤ 300, topic ≤ 50 (a plain string; the topic list is versioned with the prompts); unique dataset_version_id+position), created by migration `0004`. `PipelineRunSourceDocument` (`pipeline_run_source_documents`: composite PK pipeline_run_id FK cascade + source_document_id FK cascade, role `main`/`additional`; the parsed documents a run read; relationship `PipelineRun.source_documents`) and `PartyPosition` (`party_positions`: statement_id FK cascade, party_id FK cascade + index, value (nullable integer; null = `no stance`; CHECK `value_range` −2..+2), Evidence as columns: evidence_source_document_id FK cascade, evidence_quote (text, exactly as the LLM returned it), evidence_page (CHECK `evidence_page_positive` ≥ 1), evidence_url (≤ 2048, the document's `source_url` for URL documents); CHECK `evidence_matches_value`: a null value has all four evidence columns null, a non-null value has document, quote and page; unique statement_id+party_id; `Statement.party_positions` ordered by party_id), created by migration `0005`. `ValidationResult` (`validation_results`: pipeline_run_id FK cascade + index, check_name ≤ 50 (`check` is an SQL reserved word), passed (Boolean, no CHECK), created_at; unique pipeline_run_id+check_name; `PipelineRun.validation_results` ordered by id, `passive_deletes`) and `ValidationReportEntry` (`validation_report_entries`: validation_result_id FK cascade + index, statement_id (nullable FK cascade), party_id (nullable FK cascade), message ≤ 500; `ValidationResult.entries` ordered by id), created by migration `0006`; both are insert-only. `PartyPosition.engine_value` (−2..+2 or `NO_STANCE = "no_stance"`) is the single mapping to what the `packages/core` match-score engine consumes. Enums (`ElectionType`, `ElectionStatus`, `SourceDocumentOrigin`, `SourceDocumentStatus`, `PipelineRunStatus`, `GenerationMode`, `DatasetVersionStatus`, `SourceDocumentRole`) are non-native strings with one CHECK each.
- `ideology_app.elections`: plain functions taking a `Session` (`create_election`, `add_party`, `list_elections`, `list_parties`) that validate input and raise `InvalidInputError` / `NotFoundError` / `DuplicateError` (all `ElectionsError`). Duplicates are detected from `IntegrityError` on flush.
- `ideology_app.pdf_text`: the PDF adapter and the only module that imports `pypdf`. `extract_pages(bytes) -> list[str]` (one string per page, NUL removed, empty pages kept as `""`) or `PdfTextError(reason, page_count)` with reasons `PDF is encrypted`, `could not read PDF: <Exc>: <msg>` (≤ 500 chars), `PDF has no pages`, `no text layer found (scanned PDF?); OCR is not supported`.
- `ideology_app.pdf_text.EXTRACTOR` = `"pypdf <version>"`, recorded in each Source Text file's `extractor` field. pypdf is `>=6.21.1` (the latest release when the 2023 bundle was extracted; 6.21.1 and 6.21.2 re-extract it identically).
- `ideology_app.source_bundle` (pure): the Source Text format and the bundle reader; the only module that parses or serialises Source Text files (as bytes; only `"\n"` separates lines). `serialise_source_text(*, party, source_url, pdf_sha256, extractor, pages) -> bytes` (front matter `bundle_format`, `party`, optional `source_url`, `pdf_sha256`, `page_count`, `extractor`, `text_sha256` as `key: json.dumps(value, ensure_ascii=True)`, then each page under `<!-- page N -->`; a text line matching `^\\*<!-- page` gets one extra leading `\`). `parse_source_text(data, *, name) -> SourceText(party, source_url, pdf_sha256, page_count, extractor, pages, content_hash)` checks UTF-8 without BOM, key order, markers, `page_count`, `text_sha256`, text on some page, ≤ 50 MiB, and the canonical form (re-serialising gives the input bytes). `read_bundle(path) -> Bundle(path, slug, country, type, date, name, parties: BundleParty(short_name, name, file, text))` checks `election.toml` (exactly `format`, `[election]` country/type/date/name, `[[parties]]` short_name/name/file, unique, `file` `^[a-z0-9][a-z0-9._-]*\.md$`), the directory name equal to the slug, no `*.pdf` anywhere, every top-level `*.md` listed, every listed file present with a matching `party`. `election_slug(country, type, date)` = `es-general-2023-07-23`, `election_slug_for`, `bundle_dir_for(root, election)`, `bundle_slug(election, root=None)` (the slug only when `<root>/<slug>/election.toml` exists). Every error is `BundleError(InvalidInputError)` with `<file>:<line>: <problem>`.
- `ideology_app.bundle_import`: `import_bundle(session, bundle) -> ImportReport` finds or creates the Election by natural key and each Party by short name (`elections.create_election` / `add_party`, in manifest order, so a fresh DB gets the same ids), checks every conflict before the first write (`BundleConflictError`: another Election or Party name, a name under another short name, a current `parsed` document without `bundle_file`, more than one current bundle row, a file equal to an older row of the Party; plus `validate_url` on `source_url`), then per file reports `unchanged` (same `content_hash`), adds a `parsed` row (`origin` `url` with `source_url`, else `upload`; `bundle_file` = `original_filename` = the file; `content_hash` = SHA-256 of the `.md`; pages from the file; no stored file) or inserts a replacement and sets the old row's `replaced_by_id`. Never commits. `check_against_bundle(session, bundle) -> list[str]` (read-only) lists every divergence: missing Election, Party or current bundle row, a different name, `content_hash`, `source_url`, `page_count`, page rows or page text, or a current `parsed` row without `bundle_file`.
- `ideology_app.http_fetch`: the HTTP adapter and the only module that does HTTP for Source Documents (stdlib `urllib`). `_OPENER` has only the Proxy, Unknown, HTTP, HTTPS, HTTPDefaultError, HTTPRedirect and HTTPErrorProcessor handlers, so `file:`/`ftp:`/`data:` (and redirects to them) fail. `_open(request, timeout)` is the single test seam. `fetch_url(url, *, max_bytes)` requests an ASCII-safe form of the URL (`_ascii_url`: non-ASCII characters in the path, query and fragment are UTF-8 percent-encoded, every ASCII character including existing `%XX` escapes is kept, a non-ASCII hostname is IDNA-encoded; callers still store the URL as given), sends `User-Agent: ideology-app/0.1 (+manifesto fetch)`, uses a 60 s timeout, rejects a `Content-Length` over `max_bytes`, reads in 1 MiB chunks up to `max_bytes`, and raises `FetchError(reason)` (≤ 500 chars): `HTTP <code>: <reason>` (the `HTTPError` is closed), `could not fetch URL: <detail>` (also for any `ValueError` such as `UnicodeError` or `http.client.InvalidURL`, so no urllib/http.client error escapes), `response is empty`, `response is too large (more than N bytes)`. No retries.
- `ideology_app.source_documents`: `add_uploaded_document(session, party_id, file_path, files_dir)` validates (Party exists, regular file, 0 < size ≤ 50 MiB, starts with `%PDF-`), inserts the row (`registered`; duplicate party+hash → `DuplicateError`), then `_store_and_parse` stores the file (`fetched`) and extracts pages (`parsed` + page rows, or `failed` + `failure_reason`). `add_url_document(session, party_id, url, files_dir, fetch=None)` checks the Party and the URL (absolute http/https with a host, no credentials, whitespace or control characters, ≤ 2048 chars; `invalid URL …` otherwise) before fetching, downloads once (cap `MAX_UPLOAD_BYTES`), and on a fetch error or a body not starting with `%PDF-` returns a `failed` row with `source_url` and `failure_reason` but no hash or file; otherwise it inserts the row with `source_url` and `original_filename` (percent-decoded last path segment) and runs the same `_store_and_parse` (which uses `set_parsed_pages`; `read_pdf_file`, `validate_url` and `set_parsed_pages` are public for `source extract` and `bundle_import`). `due_url_document_ids(session, *, now, interval, election_id=None) -> list[int]`: current (`replaced_by_id` null) `parsed` URL documents that are not bundle rows (`bundle_file` null) whose `last_checked_at or created_at` (naive SQLite values read as UTC, compared in Python) is `<= now - interval`, in id order, optionally of one Election (`NotFoundError` if unknown). `refetch_url_document(session, document_id, *, now, files_dir, fetch=None, interval=None) -> RefetchOutcome(document_id, result, replacement, duplicate_of_id, reason)` (frozen; `RefetchResult` `unchanged`/`replaced`/`duplicate`/`failed`): loads the row `with_for_update()` (`NotFoundError`; `InvalidInputError` for a bundle row (`… was imported from a source text bundle; it is never re-fetched`), or if it is not a current parsed URL document or, with `interval`, no longer due), sets `last_checked_at = now`, re-validates the stored URL, fetches, checks `%PDF-`; same hash → `unchanged`; a hash another document of the same Party has → `duplicate` (no row, file or run); otherwise extracts pages **before** inserting, then inserts a new `parsed` row (same Party, `origin=url`, `source_url`, `original_filename`, `last_checked_at = now`), stores `<hash>.pdf` and sets the old row's `replaced_by_id`; an invalid URL, `FetchError`, non-PDF body or `PdfTextError` → `failed` with only `last_checked_at` written; a unique-constraint race → `DuplicateError`. Never commits. `list_documents`, `get_document`. Reuses the `elections` error classes.
- Migrations: Alembic in `src/ideology_app/migrations/` (`script_location = ideology_app:migrations` in code; root `alembic.ini` for developer commands). `env.py` reads the URL from the config or `database_url()`, supports offline `--sql`, uses `render_as_batch=True`, and disposes its engine.
- A CHECK added to an existing table is not detected by autogenerate; write it by hand inside `op.batch_alter_table` (as `0003` does).
- Add a migration: change `models.py`, then `DATABASE_URL=sqlite:///<scratch>/gen.db .venv/bin/alembic -c alembic.ini upgrade head` and `... revision --autogenerate --rev-id 000N -m "..."`, review the file by hand (see `CONSTRAINTS.md`), and check `... alembic -c alembic.ini check` reports no drift. `tests/test_migrations.py` checks upgrade/downgrade, drift and the offline PostgreSQL render.

## LLM Providers

- Package `src/ideology_app/llm/`: `base.py` (`LLMRequest[T]` with `task`, `system`, `prompt`, `schema` (a pydantic model), `max_tokens=4096`; `LLMResult[T]` with `output`, `provider`, `model`, `input_tokens`, `output_tokens`; the `LLMProvider` protocol with `name`, `model`, `generate(request) -> LLMResult`; errors `LLMError` > `LLMConfigError` (also a `config.ConfigError`), `LLMOutputError`, `LLMProviderError`), `fake.py` (`FakeProvider`), `anthropic_provider.py` (`AnthropicProvider`), `claude_code_provider.py` (`ClaudeCodeProvider`), `__init__.py` (re-exports, `PROVIDERS` registry, `build_provider`).
- Selection: `build_provider(llm_settings())`. `PROVIDERS` / `build_provider` is the only place that branches on the provider name. Callers depend on the `LLMProvider` protocol, never on a concrete class.
- Configuration (`ideology_app.config`): `LLM_PROVIDER` (`anthropic` default, `claude_code` (local Operator use only) or `fake`), `LLM_MODEL` (default per provider from `DEFAULT_MODELS`: `anthropic` -> `claude-sonnet-5-5`, `claude_code` -> `claude-sonnet-4-6` (the full id of the CLI's `sonnet` alias in Claude Code 2.1.110; `LLM_MODEL=sonnet` also works), `fake` -> `fake-model`), `LLM_CLAUDE_CODE_BIN` (default `claude`), `LLM_CLAUDE_CODE_TIMEOUT_SECONDS` (per CLI call, default 900) and `LLM_CLAUDE_CODE_MAX_WAIT_HOURS` (total usage-limit wait per call, default 48) read by `claude_code_settings() -> ClaudeCodeSettings(bin, timeout_seconds, max_wait_hours)` (the two numbers: ASCII digits, at least 1, else `ConfigError` `Invalid <NAME> '<raw>'; expected a positive integer`), `SOURCE_REFETCH_INTERVAL_HOURS` (ASCII digits only, at least 1, default `DEFAULT_SOURCE_REFETCH_INTERVAL_HOURS = 6`; `source_refetch_interval() -> timedelta`; else `ConfigError` `Invalid SOURCE_REFETCH_INTERVAL_HOURS '<raw>'; expected a positive integer`), `GENERATION_MODE` (`GenerationMode.PRECOMPUTED` default, or `LIVE`; its only behaviour is the `pipeline.triggers.QUEUE_ON_SOURCE_CHANGE` table, see Pipeline; otherwise it is recorded on each run). Values are trimmed, case-insensitive, and blank means unset. Invalid values raise `ConfigError` (a `ValueError`) listing the supported values. `VALIDATION_MIN_PARTY_COVERAGE_PERCENT` (ASCII digits only, 0..100, default `DEFAULT_MIN_PARTY_COVERAGE_PERCENT = 60`, lowered from 70 by `pipeline-balanced-statements` (user decision 2026-10-22); trimmed, blank = unset; anything else raises `ConfigError` `Invalid VALIDATION_MIN_PARTY_COVERAGE_PERCENT '<raw>'; expected an integer from 0 to 100`) , `VALIDATION_MIN_STATEMENTS` / `VALIDATION_MAX_STATEMENTS` (ASCII digits only, at least 1, defaults `DEFAULT_MIN_STATEMENTS = 25` / `DEFAULT_MAX_STATEMENTS = 35`; else `Invalid VALIDATION_MIN_STATEMENTS '<raw>'; expected a positive integer`; a min above the max, defaults included, raises `Invalid statement count range: VALIDATION_MIN_STATEMENTS (<min>) is greater than VALIDATION_MAX_STATEMENTS (<max>)`) and `VALIDATION_MAX_TOPIC_SHARE_PERCENT` (0..100, default `DEFAULT_MAX_TOPIC_SHARE_PERCENT = 30`, same message shape as the coverage variable) are read by `validation_settings() -> ValidationSettings` (see Validation), checked in the order coverage, min, max, range, share; the first error wins. `ANTHROPIC_API_KEY` is read only by `AnthropicProvider`, lazily on the first `generate`.
- `FakeProvider(responses, model="fake-model")`: canned responses keyed by `task` (dict, schema instance, or callable `(request) -> dict | model`), validated against the schema; records `calls`; deterministic word-count token numbers. Unknown task -> `LLMError`; schema mismatch -> `LLMOutputError`.
- `AnthropicProvider(model, *, client=None, api_key=None, max_retries=2, timeout=120.0)`: `client.messages.parse(..., output_format=request.schema)` (SDK structured output, `output_config.format.type == "json_schema"`). Maps `pydantic.ValidationError`, refusals and missing parsed output to `LLMOutputError`, and `anthropic.APIError` to `LLMProviderError` (class name and HTTP status only). Closes only a client it created (`close()` / `with`). Retries are the SDK's `max_retries`.
- `ClaudeCodeProvider(model, *, settings=None, runner=None, which=None, clock=None, sleep=time.sleep, log=None)` (local Operator use only; never a deployment): each `generate` runs the Operator's Claude Code CLI once through the module seam `run_cli` (`subprocess.run`, the only `subprocess` use in `llm/`) with argv `[<resolved bin>, -p, --output-format json, --verbose, --model <model>, --system-prompt <system>, --json-schema <schema.model_json_schema()>, --tools "", --no-session-persistence, --setting-sources "", --strict-mcp-config, --disable-slash-commands]` (never `--bare`, which forces API-key auth), the prompt on stdin, a fresh empty `tempfile.TemporaryDirectory(prefix="ideology-claude-")` as cwd, and a child env = `os.environ` minus every `ANTHROPIC_*` / `CLAUDE*` name except `CLAUDE_CODE_OAUTH_TOKEN` and `CLAUDE_CONFIG_DIR`, plus `CLAUDE_CODE_DISABLE_{CLAUDE_MDS,AUTO_MEMORY,ATTACHMENTS,NONESSENTIAL_TRAFFIC,THINKING}=1` and `CLAUDE_CODE_MAX_OUTPUT_TOKENS=<max_tokens>`. No key is read. The constructor (so `build_provider`, before any DB write) resolves the bin with the seam `find_cli` (`shutil.which`; missing -> `LLMConfigError` `Claude Code CLI '<bin>' not found on PATH; install it or set LLM_CLAUDE_CODE_BIN`) and runs `claude auth status --json` (30 s); a non-zero exit, unparsable JSON, `loggedIn` not true or an `authMethod` other than `claude.ai` / `oauth_token` -> `LLMConfigError`. Output: the last `type == "result"` element of the JSON array (or the bare result object); success (`subtype == "success"`, `is_error` false) validates `structured_output` against the schema (missing/invalid -> `LLMOutputError`); tokens = `input_tokens + cache_creation_input_tokens + cache_read_input_tokens` and `output_tokens`. Errors, in order: usage limit (a `rate_limit_event` with `status: "rejected"`, or a result text starting `You've hit your` / `You're out of extra usage`; never the substring "usage limit") -> wait until the reset (`resetsAt` epoch, else the text after ` · resets ` such as `3pm (Europe/Madrid)` or `Oct 23, 3:30pm (Europe/Madrid)`) + `USAGE_LIMIT_MARGIN` (2 min, at least 60 s), or `USAGE_LIMIT_FALLBACK_WAIT` (30 min) when unknown, logging one stderr line, sleeping in ≤ 60 s slices until the clock reaches the target, then retrying the identical call; waits beyond `max_wait_hours` in total -> `LLMProviderError` without sleeping; auth (`api_error_status` 401/403 or assistant error `authentication_failed`) -> `LLMConfigError`, no retry; transient (status 429 not a usage limit, 500/502/503/504/529, assistant `server_error` / `rate_limit`, `subprocess.TimeoutExpired`) -> `TRANSIENT_RETRIES = 3` retries after `TRANSIENT_BACKOFF = (30, 120, 300)` s, then `LLMProviderError`; `error_max_structured_output_retries` or assistant `max_output_tokens` -> `LLMOutputError`; non-JSON stdout, no result element and anything else -> `LLMProviderError`. Messages carry the task, subtype, `api_error_status`, exit code and at most 200 characters of the CLI text (or stderr), never the prompt or env. `KeyboardInterrupt` propagates, so `runs.py` records `failed: interrupted`. `close()` is a no-op. The process must stay alive for one run; a run that stops halfway can be resumed with `pipeline run --resume-from` (see Pipeline, `checkpoint.py`).
- Dependency direction: `config` -> `llm`. `config` never imports `llm`. `pipeline` imports only `llm.base`; `cli` imports `build_provider` (in `cli._provider`).
- Add a provider: write `src/ideology_app/llm/<name>_provider.py` implementing the protocol, add one entry to `PROVIDERS` and one to `config.DEFAULT_MODELS`.
- Tests: `tests/test_llm.py` (config, registry, fake), `tests/test_llm_anthropic.py` (adapter through an injected `anthropic.Anthropic` with an `httpx2.MockTransport` `http_client`) and `tests/test_llm_claude_code.py` (fake runner, clock, sleep and log; envelope builders in the 2.1.110 shapes; its guard also replaces the `run_cli` / `find_cli` seams with failing stubs; `tests/pipeline_fixtures.offline_guard` stubs `run_cli` too). Each has an autouse guard that unsets the LLM env vars and blocks `socket.socket.connect` / `socket.create_connection`.

## Pipeline

- Package `src/ideology_app/pipeline/`: `prompts.py` (topics, schemas, versioned prompts), `generation.py` (chunking and Statement LLM calls, no database), `positions.py` (Party Position LLM calls, no database), `runs.py` (Pipeline Run service), `publishing.py` (publish and supersede Dataset Versions), `agenda.py` (the Party-balanced Agenda: pure, no database or LLM), `selection.py` (Statement Selection: pure, no database or LLM), `reports.py` (read-only Pipeline Run report), `triggers.py` (the `live` source-change trigger), `__init__.py` (re-exports). Dependency direction: `models` / `elections` (errors) / `llm.base` → `pipeline` → `cli`. It never imports a concrete provider; the provider is injected.
- `prompts.py`: `Topic` (a `Literal` of 18 slugs, `economy` … `infrastructure_transport`) and `TOPICS`; schemas `StatementDraft` (`text` 1..300 chars with a non-space character, `topic: Topic`), `CandidateList` (`candidates`, ≤ 12), `StatementSet` (`statements`, 1..60); `PromptSpec(task, version, system, template, schema, max_tokens)` with `STATEMENT_CANDIDATES` (`v1`, 4096 tokens, field `{chunk}`) and `GENERATE_STATEMENTS` (`v4`, 16384 tokens, fields `{candidates}`, `{count}`, `{min_count}`, `{max_count}`; it asks for the Statement Pool); `POSITION_FINDINGS` (`position_findings`, `v3`, 4096 tokens, fields `{statements}`, `{chunk}`; schema `FindingList(findings ≤ 60 of Finding(statement ≥ 1, value −2..+2, quote 1..500 chars with a non-space, page ≥ 1))`) and `PARTY_POSITIONS` (`party_positions`, `v2`, 8192 tokens, fields `{statements}`, `{candidates}`; schema `PositionList(positions ≤ 60 of PositionChoice(statement ≥ 1, value −2..+2, evidence ≥ 1))`); `PROMPT_VERSIONS` (task → version for all four tasks, recorded on every run: `statement_candidates` v1, `generate_statements` v4, `position_findings` v3, `party_positions` v2); `POOL_MIN_STATEMENTS = 45`, `POOL_MAX_STATEMENTS = 60`, `POOL_TARGET_STATEMENTS = 55` (`pipeline-coverage-selection`). The static `StatementSet`, `FindingList` and `PositionList` are base types only (and `PromptSpec.schema`); requests always send the bounded schema of a cached builder (`pipeline-output-bounds`), a `create_model` subclass with the same class name and docstring (so schema titles and `does not match <Name>` errors are unchanged); each argument must be an `int` ≥ 1, else `ValueError`: `statement_set_schema(min_statements, max_statements)` (`statements` min..max, min ≤ max), `finding_list_schema(statement_count)` (`Finding.statement` 1..N, `findings` ≤ 60) and `position_list_schema(statement_count, candidate_count)` (`PositionChoice.statement` 1..N, `evidence` 1..K, `positions` ≤ N). Prompts are in Spanish and state the single-proposition, neutral-wording, 5-point-scale and topic rules; the reduce prompt (v4, `pipeline-balanced-statements`) says its candidates come in equal number from several manifestos and a later automatic procedure chooses the questionnaire from its list, and asks for orientation-level Statements (one policy direction with a clear sense, no figures, percentages, deadlines or named laws or plans), grouping candidates of different manifestos on the same axis in either direction, contested orientations (not ones almost every manifesto would sign), varied direction (also reduce, limit or abolish), nothing beyond the candidates, topic spread (no topic over about a quarter) and no near-duplicates (`_COMMON_RULES`, shared with `statement_candidates`, is unchanged); the findings prompt (v3) keeps "only what the chunk treats explicitly", the ban on deducing from general ideology and the verbatim-quote rule, and adds that a concrete proposal clearly going in a Statement's direction (agree) or the opposite one (disagree) counts as treating it, with the quote containing that proposal, and that silence is not a stance; its template asks for "una lista de `{count}` afirmaciones (como mínimo `{min_count}` y como máximo `{max_count}`)" with the `pool_bounds` target and bounds.
- `generation.py`: `CHUNK_MAX_CHARS = 40_000`, `MAX_LLM_CALLS_PER_RUN = 200`. `build_document_chunks(documents)` returns `Chunk(party_id, document_id, text)`; `build_chunks(documents)` is its texts (pure; `DocumentPages(party_id, document_id, pages, source_url=None, role=main)`): documents ordered by Party id then document id, pages by number; each page rendered as `[página N]\n<text as stored>`, pages joined by a blank line; a chunk holds whole consecutive pages of one document and is at most the limit (a page over the limit is cut into consecutive slices, each under its marker); whitespace-only pages are left out. `generate_statements(provider, chunks: Sequence[Chunk], usage, settings=None) -> StatementPool(statements, agenda)` (frozen): map (one `statement_candidates` call per chunk, on `chunk.text`; the request is byte-identical to before), then `agenda.balance_candidates([(chunk.party_id, candidates)…], pool_max=pool_bounds(settings)[1])`, then reduce (the agenda's candidates, with exact duplicates removed, sorted by (topic, text), one `generate_statements` call built by `reduce_request(candidates, settings)`, whose schema is `statement_set_schema(low, high)` from `pool_bounds(settings) -> (low, high, target)`: `low = max(POOL_MIN_STATEMENTS, settings.max_statements)`, `high = max(POOL_MAX_STATEMENTS, low)`, `target = min(max(POOL_TARGET_STATEMENTS, low), high)` (45, 60, 55 with the defaults; the pool is never smaller than the largest allowed Questionnaire); `settings` is a `config.ValidationSettings`, `None` meaning its defaults; env is never read here). It returns the Statement Pool with its agenda. An out-of-range pool size fails that call with `LLMOutputError`. `Usage` (calls, input/output tokens) is updated after each successful call. `GenerationError` for `too many chunks: <n> (limit 199)` (before any call) and `no statement candidates were found in the source documents` (empty agenda, before the reduce call); `LLMError` propagates.
- `agenda.py` (`pipeline-balanced-statements`; pure: imports only `prompts`; no database, LLM, clock or randomness, no iteration over unordered sets): `AGENDA_VERSION = "v1"`, `PARTY_QUOTA_MAX = 24`, `balance_candidates(per_chunk: Sequence[(party_id, candidates)], pool_max) -> Agenda(candidates, quota, report)` (frozen). Per Party its unique `(topic, text)` in first-seen order with `chunk` (0-based among its chunks) and `rank` (index in that chunk's output); `P` = Parties with at least one; `quota = max(ceil(pool_max / P), min(PARTY_QUOTA_MAX, min n_p))` (12 for the 2023 run-1 shape: 9 Parties, EH Bildu 12); each Party contributes `min(n_p, quota)` (a short Party gives all it has, nothing is invented). Within a Party, topics ordered by count desc, first `(chunk, rank)`, then `TOPICS` order; within a topic by `(rank, chunk)`; picks round-robin over topics. The union is deduplicated and sorted by `(topic, text)`, so the reduce prompt carries no Party id, name or order (permuting Party ids leaves the request identical). `report` (JSON): `version`, `pool_max`, `floor`, `quota_max`, `quota`, `lines`, `parties` (every Party seen, in id order: `party_id`, `chunks`, `candidates`, `unique`, `picked`). Dependency: `prompts` → `agenda` → `generation`.
- `positions.py`: `MAX_POSITION_CALLS_PER_RUN = 300`; `plan_position_calls(documents)` = chunks + Parties with at least one chunk (an upper bound). `extract_positions(provider, statements, documents, party_ids, usage)`: Parties in id order; each chunk of a Party's documents (main document first, then document id, then page; the same 40,000-character chunks) gets one `position_findings` call whose prompt lists the Statements as `[n] <text>` and then the chunk; findings become numbered candidates `C<k> [programa principal|programa adicional] [afirmación n] [valor v] [página p] «quote»`, and one `party_positions` call per Party picks one stance per Statement and the candidate it cites (any candidate for any Statement). No candidates → no reduce call. Returns exactly n `PositionResult(statement_number, value, document_id, quote, page, url)` per Party; omitted Statements and Parties without documents are `no stance`. `findings_request(statements, chunk, statement_count)` and `positions_request(statements, candidates, statement_count)` send `finding_list_schema(N)` and `position_list_schema(N, K)` (N Statements listed, K candidates listed), so an unknown Statement or evidence number, or more than N choices, fails that call with `LLMOutputError` (since `pipeline-output-bounds`; the former `referred to unknown statement` / `unknown evidence candidate` `GenerationError`s are gone). `GenerationError` only for `party_positions repeated statement <n>`; `LLMError` propagates. Quotes and pages are kept as returned (no Validation here). Coalition precedence is a prompt rule: the main (joint) manifesto wins on conflict.
- `runs.py`: `queue_run(session, election_id, *, llm_provider, llm_model, generation_mode)` (Election must exist and have a `parsed` Source Document; flushes a `queued` run; the caller commits). `execute_run(engine, run_id, provider, validation_settings=None) -> RunOutcome` first resolves `validation_settings` (`None` → `config.validation_settings()`, so an invalid value raises `ConfigError` before any write or LLM call), then commits at two points: (1) checks the run is `queued` and the provider's `name`/`model` equal the recorded ones (else `InvalidInputError`, nothing changed), records a `pipeline_run_source_documents` row per current parsed document (`_parsed_documents_query` also requires `replaced_by_id IS NULL`, so `queue_run`, `_start` and the trigger never see a replaced row; documents are ordered by `(party_id, lineage root, id)`, where the lineage root is the id of a document's first version found by following `replaced_by_id` backwards, so each Party's document with the lowest root is `main` and a re-fetched main manifesto stays `main`; the others are `additional`), sets `running` + `started_at` and loads the parsed pages (with `source_url` and role) and the Election's Party ids as plain data; then, outside any transaction, checks the position call budget (`too many position extraction calls: <n> (limit 300)`, before any LLM call), generates the Statement Pool (`generate_statements(provider, build_document_chunks(documents), ..., settings=validation_settings)`: the same resolved object gives the pool bounds of the `generate_statements` schema, drives the selection and is later given to `validate_run`), extracts the positions for the whole pool (the call count does not depend on the pool size) and selects the Questionnaire (`selection.select_statements(pool, positions, party_ids, validation_settings)`); (2) in one commit (`_finish(..., selection={**selection.report, "agenda": pool.agenda.report})`) inserts a `candidate` `DatasetVersion`, the selected Statements at positions 1..n (pool order) exactly as returned, n × Parties `PartyPosition` rows (value and Evidence of the extraction) and `pipeline_runs.statement_selection`, and sets `validating`, then (3) calls `validate_run(..., settings=validation_settings)` outside its own `try` and returns that outcome (see Validation); or on `LLMError` / `GenerationError` sets `failed` with `str(exc)[:500]` and no Dataset Version; `KeyboardInterrupt` sets `failed` with `interrupted` and is re-raised; any other exception sets `failed` with `unexpected error: <ClassName>` and is re-raised. The source-document rows of a failed run remain. Both record usage and `generation_finished_at`. `RunOutcome` has `statement_count`, `position_count` and `failed_checks`. `list_runs(session, election_id)`, `list_queued_run_ids(session, election_id=None) -> list[int]` (`queued` runs in id order, of one Election or all; `NotFoundError` for an unknown Election), `find_unfinished_run(session, election_id, provider=None, model=None) -> UnfinishedRun(run_id, status, recorded_calls) | None` (read-only, `shared-database`: the Election's highest-id run with at least one recorded call, returned only when it has no Dataset Version, is `running` or `failed`, and matches the given provider/model), `get_dataset_version(session, id)`, `list_positions(session, dataset_version_id, party_id=None)` (ordered by Statement position then Party id; `NotFoundError` for an unknown version or a Party not in its Election). No update or delete path for Dataset Versions, Statements or Party Positions.
- `publishing.py` (imports `sqlalchemy` and `models` only, never commits): `PublishOutcome(election_id, published, published_dataset_version_id, published_run_id, superseded_dataset_version_id=None)` (frozen; `published_*` names the version live after the call). `election_lock_statement(election_id)` = `select(Election)…with_for_update()`. `get_published_dataset_version(session, election_id)` (`None` before the first publish). `publish_dataset_version(session, version)`: `ValueError` unless the version is `candidate`; locks the Election row; if the current Published version belongs to a run with a higher id, returns `published=False` with that version's ids and changes nothing (publish order = Pipeline Run id, i.e. queue order; Dataset Version ids follow finish order and are not used); otherwise sets the current one `superseded` and flushes **before** setting the new one `published` (the unit of work orders UPDATEs by primary key, so without that flush the partial index could see two Published rows), sets a `draft` Election `active` (`active`/`archived` stay), and flushes. Concurrency: on PostgreSQL the `FOR UPDATE` row lock serialises publishers of one Election; on SQLite (`FOR UPDATE` is dropped) `validate_run` publishes after its first write (the results flush), which holds the database write lock, so a second finisher waits (pysqlite's 5 s busy timeout) and then reads the committed Published version; the partial unique index is the backstop (`IntegrityError` → rollback).
- `checkpoint.py` (`pipeline-run-checkpoint`): `CheckpointProvider(inner, engine, run_id, resumed_from_run_id=None)` wraps the injected provider for every run (`execute_run` builds it after `_start`). Each successful call is inserted into `pipeline_run_calls` (`sequence`, `task`, `request_hash`, the validated `output` as JSON, tokens, `reused`) in its own `session_scope` commit right after it returns; a failed call stores nothing. `request_hash(provider, model, request)` is the SHA-256 of canonical JSON (sorted keys) of provider, model, task, system, prompt, the schema's JSON schema and `max_tokens`. With `resumed_from_run_id` the wrapper loads that run's calls in sequence order; before each call it takes the first unused one with the same hash, re-validates it against the request schema (a stored output that no longer validates is skipped as a miss) and returns it with zero tokens, recording it with `reused = true`, without calling the provider. Reused rows are recorded too, so resuming from the latest run is enough after several stops. `count_recorded_calls(engine, run_id)`. `queue_run(..., resumed_from_run_id=None, allow_finished_source=False)` stores `pipeline_runs.resumed_from_run_id` (no FK) after `_check_resumable`: the run must exist (`NotFoundError`), belong to the same Election, have the same provider/model and, unless `allow_finished_source` (`--reuse-from`), have no Dataset Version (`InvalidInputError`). `llm_calls` counts reused calls; tokens count only provider calls. Reuse is explicit only: without `--resume-from` or `--reuse-from` every call goes to the provider.
- `selection.py` (`pipeline-coverage-selection`; pure: no database, LLM, clock or randomness, no iteration over unordered sets): `select_statements(pool, positions, party_ids, settings) -> Selection(statements, positions, report)` (frozen). Scores per pool Statement: `stances`, `distinct` values, `spread` (max − min). It reuses the Validation check functions on the pool as a `ValidationInput` (id = position = pool number): `check_statement_uniqueness` makes later copies ineligible (`duplicate`, `duplicate_of` = the first in pool order); `check_statement_separation` splits the rest into tier 1 (separating) and tier 2 (all of them with fewer than two Parties). `topic_cap(settings) = max(1, max_topic_share_percent * min_statements // 100)` (7 with the defaults). Greedy leximin: repeatedly the tier-1 Statement (topic not full) with the largest key (sorted per-Party coverage counts after adding it, then `distinct`, `spread`, lower pool number), up to `max_statements`; tier 2 only to reach `min_statements`. Count: ≤ `min_statements` picks → all (`short`); else the largest prefix in `[min_statements, L]` on which `check_party_coverage` passes (`coverage_met`), else the one with the best worst-Party ratio (integer comparison, ties to the larger; `best_coverage`). The selected Statements keep pool order, text and topic and are renumbered 1..n; each `PositionResult` is copied with `dataclasses.replace(statement_number=new)`. The report (`SELECTION_VERSION = "v1"`, JSON) holds the settings, `topic_cap`, `party_ids`, pool size, count and rule, `projected_failures` (`run_checks` on the selection without `evidence_quotes`; informational), per-Party pool/selected stance counts and one entry per pool Statement (text, topic, values in `party_ids` order, scores, tier, status `selected|duplicate|topic_full|not_picked`, `duplicate_of`, `pick`, `position`). Dependency: `config`, `validation`, `prompts`, `positions` → `selection` → `runs` (`validation` never imports `pipeline`).
- `reports.py` (read-only: `SELECT`s only, no write path): `get_run_report(session, run_id) -> RunReport` (`NotFoundError` for an unknown run). `RunReport` is frozen: the run's stored fields (status, failure_reason, provider, model, Generation Mode, prompt_versions, timestamps, usage, `validation_settings`), `validated_at` (`min(validation_results.created_at)`), the Dataset Version's id, status and Statement count (`None` without one), the Election's live version (`live_dataset_version_id`, `live_run_id` from `publishing.get_published_dataset_version`), `statement_selection` (the stored report, or `None`) and `results` (`list_validation_results`, ORM rows read inside the caller's session). Formatting is the CLI's (`pipeline report`). Dependency: `models`, `publishing`, `runs` → `reports` → `cli`.
- A successful run ends `passed` or `failed` after Validation; a `passed` run publishes its Dataset Version in the same commit (see `validate_run`). A hard kill or crash still leaves a run `running` (no recovery command); one left in `validating` is finished with `ideology pipeline validate --run N`.
- `triggers.py` (never commits, never calls an LLM or builds a provider): `QUEUE_ON_SOURCE_CHANGE: dict[GenerationMode, bool]` (`precomputed` → `False`, `live` → `True`; the only place that gives Generation Mode a behaviour; a test asserts every member has an entry) and `queues_on_source_change(mode)`. `queue_run_for_source_change(session, document, *, generation_mode, llm: LLMSettings | None) -> SourceChangeOutcome(election_id, run_id, newly_queued)` (frozen): writes nothing when the mode does not queue or the document is not `parsed`; `ValueError` when the mode queues and `llm` is `None`; otherwise locks the Election row (`publishing.election_lock_statement`), returns the lowest-id `queued` run of the Election (`newly_queued=False`) or calls `runs.queue_run` with `llm.provider` / `llm.model` (`newly_queued=True`). Coalescing: at most one `queued` run per Election; it reads every current parsed document when it starts (`_start`). `source refetch` calls it the same way for a replacement document. `running` / `validating` runs do not suppress queuing (they loaded their input already), so the worst case per Election is one in-flight run plus one queued run. `source add` calls it inside its own `session_scope`, so the document and its run commit together. Queued runs are executed only by the Operator (`pipeline run-queued`); there is no worker, scheduler or background thread. `pipeline run` queues and executes its own run synchronously in both modes.
- Bump a prompt: edit `prompts.py`, change that prompt's `version` (e.g. `v2`), and replace its `(task, version)` entry in `FINGERPRINTS` in `tests/test_pipeline_prompts.py` with the fingerprint the failing test prints. Each prompt is pinned with a reference schema (`REFERENCE_SCHEMAS`: `CandidateList`, `statement_set_schema(45, 60)`, `finding_list_schema(30)`, `position_list_schema(30, 10)`), so a builder change fails the pin too; `CANDIDATE_REQUEST_HASH` pins the `statement_candidates` request hash so its recorded calls stay reusable.
- Tests: `tests/pipeline_fixtures.py` (ORM seeding, default fake responses for all four tasks, `chunk_pages` / `candidate_lines` request parsers, `offline_guard`), `tests/test_pipeline_prompts.py`, `tests/test_pipeline_generation.py`, `tests/test_pipeline_agenda.py`, `tests/test_pipeline_positions.py`, `tests/test_pipeline_runs.py`, `tests/test_publishing.py`, `tests/test_cli_pipeline.py`, `tests/test_cli_pipeline_report.py`, `tests/test_pipeline_triggers.py`, `tests/test_cli_live_mode.py`, `tests/test_source_refetch.py`, `tests/test_cli_source_refetch.py` (HTTP mocked through `fetch=` or `http_fetch._open`, clock through `now=` or `cli._now`), each with the autouse env/socket guard (also `tests/test_cli_source.py` and `tests/test_source_url.py` unset `GENERATION_MODE` / `LLM_*`).

## Validation

- Package `src/ideology_app/validation/`: `base.py` (data and `load_input`), `evidence_quotes.py` (check 2), `party_coverage.py` (check 3), `statement_separation.py` (check 4), `statement_uniqueness.py` (check 1, uniqueness part), `statement_count.py` (check 5), `topic_spread.py` (check 6), `__init__.py` (`CHECKS`, `run_checks`, re-exports incl. `ValidationSettings`). Dependency direction: `config` / `models` → `validation` → `pipeline.runs` → `cli`. It never imports `pipeline`, `llm` or `pdf_text`, and never reads the environment itself.
- `config.ValidationSettings(min_party_coverage_percent=60, min_statements=25, max_statements=35, max_topic_share_percent=30)`: frozen; `__post_init__` raises `ValueError` unless each value is an `int` (not `bool`): the two percents in 0..100, the two counts at least 1, and `min_statements <= max_statements`. It is how checks get thresholds: one process-wide value (no per-Election override; recorded on the run as `pipeline_runs.validation_settings` by `validate_run`), read by `config.validation_settings()` and passed explicitly: `validate_run(..., settings)` / `execute_run(..., validation_settings)` → `load_input(session, run, settings)` → `ValidationInput.settings`.
- `ValidationInput(statements, positions, party_ids, documents, settings=ValidationSettings())`: plain frozen data. `statements` are `StatementRow(id, position, text, topic)` in position order; `positions` are `PositionRow(statement_id, statement_position, party_id, value, document_id, quote, page, url)` by Statement position then Party id (`value` None = `no stance`); `party_ids` the Election's Parties in id order; `documents` maps document id → `RunDocument(party_id, role, source_url, pages: {page_number: text})` for every `pipeline_run_source_documents` row. `settings` the thresholds. `load_input(session, run, settings)` builds it and is the only database read for checks.
- `Check(name, run)`: `name` is a stable slug ≤ 50 chars; `run(ValidationInput) -> list[ReportEntry]`. `ReportEntry(message, statement_id=None, party_id=None)` (message ≤ 500; cut when stored). `CheckResult(name, entries)`, `passed = not entries`. `CHECKS: tuple[Check, ...] = (EVIDENCE_QUOTES, PARTY_COVERAGE, STATEMENT_SEPARATION, STATEMENT_UNIQUENESS, STATEMENT_COUNT, TOPIC_SPREAD)`: registry order is run order, and new checks are appended (so existing result rows and `failure_reason` strings stay stable); `run_checks(data, checks=CHECKS)` runs every check in registry order with no short-circuit.
- Checks are pure functions of `ValidationInput`: no database, LLM, network or clock.
- Add a check: write `validation/<name>.py` exporting a `Check` and append it to `CHECKS`. If it needs more run data, add a field to `ValidationInput` and fill it in `load_input`; if it needs a threshold, add a field to `config.ValidationSettings` plus its env reading in `config.validation_settings()` (never a literal in the check). Storage, the CLI and the run transition need no change.
- `pipeline.runs.validate_run(engine, run_id, checks=CHECKS, settings=None) -> RunOutcome`: `settings=None` → `config.validation_settings()`, read first, before any session (an invalid value raises `ConfigError` and changes nothing). Unknown run → `NotFoundError`; not `validating` → `InvalidInputError` (`pipeline run N is <status>, expected validating`), nothing changed. Otherwise, in one commit, inserts one `ValidationResult` per check (with its entries, in order), records `dataclasses.asdict(settings)` in `run.validation_settings` (both outcomes; never on the rollback path) and sets `passed`, or `failed` with `validation failed: <failed names, comma-separated>` (≤ 500). On `passed`, the same session then calls `publishing.publish_dataset_version` (supersede, publish, Election `draft` → `active`), so the results, the status and the publication share one commit; on `failed` the Dataset Version stays `candidate` and no status changes. `RunOutcome.publish` is the `PublishOutcome` (`None` unless `passed`). If a check or the publish step raises, the transaction rolls back (no result rows, no status change), the run is set `failed` with `unexpected error: <ClassName>` (Ctrl-C: `interrupted`) in a new session, and the exception is re-raised. `list_validation_results(session, run_id)` (check order, entries with their Statement; `NotFoundError` for an unknown run).
- `evidence_quotes` (`validation/evidence_quotes.py`): `normalize_for_match(text)` = NFKD, `casefold()`, NFKD, then keep only `isalnum()` characters that are not combining marks (accents, case, ligatures, NBSP, soft hyphens, all whitespace and punctuation fold or drop; word order and every letter and digit still count). `quote_starts_on(norm_quote, norm_pages, page)`: the quote occurs in page + next page at an index inside the cited page. For each stance (non-null value), in input order, the first failing rule becomes one entry with its `statement_id` and `party_id`: (1) the document is a run document of the same Party, else `source document D is not a source document of party P in this run`; (2) `url` equals the document's `source_url` (both null for uploads), else `evidence URL does not match source document D`; (3) the page exists, else `page P does not exist in source document D (N pages)`; (4) the normalised quote is non-empty, else `quote has no letters or digits`; (5) the quote starts on the cited page, else `quote not found on page P of source document D (found on page Q)` (first other page, in page order, where it starts) or `quote not found in source document D`. Pages are normalised lazily, once per document per check. No edit distance, no minimum length; stored quotes and page text are never changed.
- `party_coverage` (`validation/party_coverage.py`): a Party is covered on a Statement when its Party Position there is not `no stance`. With `total = len(statements)` (0 → no entries: coverage is undefined and the count is another check's job), stances are counted per Party id in `party_ids` (positions of other Party ids are ignored); a Party fails when `covered * 100 < percent * total` (integers only, so exactly the minimum passes). One entry per failing Party, in `party_ids` order, with `party_id` and no `statement_id`: `party P has positions on C of N statements (F%); minimum is T%` (`F = C * 100 // N`, floored, so always below `T`). A failing Party fails the whole run; it is never excluded.
- `statement_separation` (`validation/statement_separation.py`, no threshold): a Statement separates the Parties when its stances (non-null values of Parties in `party_ids`) hold at least two different values; `no stance` is ignored, and `0` is a stance like any other. Zero Statements → no entries (checked first). Fewer than two Parties in `party_ids` → one Election-level entry with no `statement_id` or `party_id`: `statements cannot separate parties: the election has N party|parties; at least 2 are needed`. Otherwise one entry per non-separating Statement, in `statements` order, with its `statement_id` and no `party_id`; `S` is the Statement position: `statement S does not separate parties: no party has a stance` / `...: only party P has a stance (value V)` / `...: all K parties with a stance have value V`. Positions of Party ids outside `party_ids` or of unknown Statement ids are ignored. A non-separating Statement fails the whole run; it is never dropped. When a Party has no stances, `party_coverage` reports that Party and `statement_separation` reports every Statement left with fewer than two stances: this double reporting is intended (checks stay independent; the message names the cause).
- `statement_uniqueness` (`validation/statement_uniqueness.py`, no threshold): two Statements are duplicates when their texts are equal after `evidence_quotes.normalize_for_match` (reused, so the repo has one normalisation rule: case, accents, ligatures, whitespace and punctuation are ignored; word order and every letter and digit count). Topic is ignored. One entry per later copy, in `statements` order, with its `statement_id` and no `party_id`: `statement S duplicates statement F` (`F` = the first Statement with that text). Paraphrases are not detected, and the single-proposition half of check 1 is not automated (prompts only). Separators are dropped, so `2,1 %` and `21 %` collide, and a text with no letters or digits normalises to `""`: both can only cause a false failure.
- `statement_count` (`validation/statement_count.py`): passes when `settings.min_statements <= n <= settings.max_statements` (inclusive). Otherwise one run-level entry (no ids): `questionnaire has N statements; expected MIN to MAX`. It owns the zero-Statements case (0 fails).
- `topic_spread` (`validation/topic_spread.py`): with `total = len(statements)` (0 → no entries), a topic fails when `count * 100 > settings.max_topic_share_percent * total` (strictly above; integers only). One run-level entry (no ids) per failing topic, in order of first appearance: `topic T has C of N statements (P%); maximum is M%` (`P = -(-C * 100 // N)`, the ceiling, so always above `M`).
- None of the three reads another check's result; any failure fails the whole run, and Statements are never dropped, deduplicated or reordered.
- Tests: `tests/test_validation_evidence_quotes.py` (plain data), `tests/test_validation_party_coverage.py` (plain data and config), `tests/test_validation_statement_separation.py` (plain data, registry prefix), `tests/test_validation_questionnaire_shape.py` (plain data and config for the three shape checks, full registry tuple), `tests/test_validation_runs.py` (`execute_run` / `validate_run`, stub checks), Validation CLI tests in `tests/test_cli_pipeline.py`, each with the autouse env/socket guard.

## Verification Gate

- `./init.sh` runs from its own directory, creates `.venv` if missing (`${PYTHON:-python3} -m venv`), then runs ordered steps through `run_step <name> <function>`, which prints `==> <name>`, runs the step in a `( set -e; ... )` subshell outside any condition (bash ignores `set -e` inside `if`/`!`/`&&`/`||`), and exits 1 with `FAILED: <name> (exit N)` on failure. So any failing command in a multi-command step fails the gate.
- Current steps: `node` (Node.js >= 22.13 on `PATH`, `NODE_MIN_MAJOR` / `NODE_MIN_MINOR`, required by Vite 8, Vitest 5 and jsdom 29; fails before anything is installed), `install` (`pip install -e '.[dev]'`), `pytest`, `web-install` (`npm ci --no-audit --no-fund`; fails when `npm` is missing or `package.json` and the lockfile disagree), `web-typecheck` (`npm run typecheck`), `web-test` (`npm test`), `web-build` (`npm run build`). Pytest runs with `filterwarnings = ["error"]`, so warnings (including leaked-connection `ResourceWarning`s) fail the gate. Migration checks run inside pytest. `tests/test_init_script.py` checks `run_step`, `step_node` and `step_web_install` by extracting them from `init.sh`.
- To add a step, define a `step_<name>` function and add a `run_step` line after the existing ones. Steps are functions so their arguments are never word-split. Keep `init.sh` compatible with macOS `/bin/bash` 3.2 (under `set -u`, check an array's length before expanding `"${arr[@]}"`).
- `init.sh` never starts a server; it only prints the start commands (uvicorn, the URL, the optional Vite dev server) after all checks pass.
