# Architecture

Current state after `db-schema-elections-parties`, `llm-provider-abstraction`, `source-document-upload`, `source-document-url`, `match-score-engine`, `pipeline-generate-statements` and `pipeline-extract-positions`. Keep this short; update it when layers, runtime surfaces or boundaries change.

## Layout

- Python package in src layout: `src/ideology_app/`, installed editable via `pip install -e '.[dev]'` (`pyproject.toml`, setuptools backend, `requires-python >=3.12`).
- Domain, pipeline and adapter modules will live under `src/ideology_app/` as features add them.
- Tests live in `tests/` and run with pytest (`[tool.pytest.ini_options]` in `pyproject.toml`).

## Data Layer

- Dependency direction: `config` → `db` → `models` → `elections` / `source_documents` / `pipeline` (services; `source_documents` also uses `pdf_text` and `http_fetch`; `pipeline` also uses `llm.base`) → `cli`. The FastAPI app does not touch the database yet.
- `ideology_app.config.database_url()`: `$DATABASE_URL`, else `sqlite:///ideology.db` (relative to the current directory; `*.db` is git-ignored). SQLite is the dev default; PostgreSQL is the target.
- `ideology_app.config.source_files_dir()`: `$SOURCE_FILES_DIR`, else `source_files/` relative to the current directory (git-ignored). Uploaded and downloaded Source Document files are stored there content-addressed as `<content_hash>.pdf` (lowercase hex SHA-256), written via a temp file + `os.replace`, never overwritten; Source Documents of different Parties with the same bytes share one file. Local disk only (no object storage yet).
- `ideology_app.db`: `make_engine(url)` (SQLite gets `PRAGMA foreign_keys=ON`), `session_scope(engine)` (commit/rollback), `alembic_config(url)`, `run_migrations(url, revision="head")`, `downgrade(url, revision)`, `is_initialised(engine)` (true only when the database's Alembic revision equals the script head, so any older schema counts as not initialised). Callers own and dispose every Engine.
- `ideology_app.models`: `Base` with a constraint naming convention (`pk_`, `fk_`, `uq_<table>_<col>_<col>`, `ck_<table>_<name>`, `ix_`); `Election` (`elections`: country, type, date, name, status; unique country+type+date) and `Party` (`parties`: election_id FK cascade, name, short_name; unique per Election). `SourceDocument` (`source_documents`: party_id FK cascade + index, origin `upload`/`url`, status `registered`/`fetched`/`parsed`/`failed`, original_filename, source_url (≤ 2048; CHECK `source_url_matches_origin`: set exactly when origin is `url`, added by hand in `0003`), content_hash, page_count, failure_reason, created_at; unique party_id+content_hash) and `SourceDocumentPage` (`source_document_pages`: source_document_id FK cascade, page_number ≥ 1, text; unique per document). `PipelineRun` (`pipeline_runs`: election_id FK cascade + index, status `queued`/`running`/`validating`/`passed`/`failed` (full domain lifecycle; this feature sets all but `passed`), llm_provider, llm_model, generation_mode (`config.GenerationMode`), prompt_versions (JSON task → version), llm_calls, input_tokens, output_tokens (default 0), failure_reason (≤ 500), created_at, started_at, generation_finished_at), `DatasetVersion` (`dataset_versions`: election_id FK cascade + index, pipeline_run_id FK cascade and unique, status `candidate`/`published`/`superseded` (default `candidate`), created_at; `statements` ordered by position) and `Statement` (`statements`: dataset_version_id FK cascade, position ≥ 1 (CHECK `position_positive`), text ≤ 300, topic ≤ 50 (a plain string; the topic list is versioned with the prompts); unique dataset_version_id+position), created by migration `0004`. `PipelineRunSourceDocument` (`pipeline_run_source_documents`: composite PK pipeline_run_id FK cascade + source_document_id FK cascade, role `main`/`additional`; the parsed documents a run read; relationship `PipelineRun.source_documents`) and `PartyPosition` (`party_positions`: statement_id FK cascade, party_id FK cascade + index, value (nullable integer; null = `no stance`; CHECK `value_range` −2..+2), Evidence as columns: evidence_source_document_id FK cascade, evidence_quote (text, exactly as the LLM returned it), evidence_page (CHECK `evidence_page_positive` ≥ 1), evidence_url (≤ 2048, the document's `source_url` for URL documents); CHECK `evidence_matches_value`: a null value has all four evidence columns null, a non-null value has document, quote and page; unique statement_id+party_id; `Statement.party_positions` ordered by party_id), created by migration `0005`. `PartyPosition.engine_value` (−2..+2 or `NO_STANCE = "no_stance"`) is the single mapping to what `match-score.js` consumes. Enums (`ElectionType`, `ElectionStatus`, `SourceDocumentOrigin`, `SourceDocumentStatus`, `PipelineRunStatus`, `GenerationMode`, `DatasetVersionStatus`, `SourceDocumentRole`) are non-native strings with one CHECK each.
- `ideology_app.elections`: plain functions taking a `Session` (`create_election`, `add_party`, `list_elections`, `list_parties`) that validate input and raise `InvalidInputError` / `NotFoundError` / `DuplicateError` (all `ElectionsError`). Duplicates are detected from `IntegrityError` on flush.
- `ideology_app.pdf_text`: the PDF adapter and the only module that imports `pypdf`. `extract_pages(bytes) -> list[str]` (one string per page, NUL removed, empty pages kept as `""`) or `PdfTextError(reason, page_count)` with reasons `PDF is encrypted`, `could not read PDF: <Exc>: <msg>` (≤ 500 chars), `PDF has no pages`, `no text layer found (scanned PDF?); OCR is not supported`.
- `ideology_app.http_fetch`: the HTTP adapter and the only module that does HTTP for Source Documents (stdlib `urllib`). `_OPENER` has only the Proxy, Unknown, HTTP, HTTPS, HTTPDefaultError, HTTPRedirect and HTTPErrorProcessor handlers, so `file:`/`ftp:`/`data:` (and redirects to them) fail. `_open(request, timeout)` is the single test seam. `fetch_url(url, *, max_bytes)` requests an ASCII-safe form of the URL (`_ascii_url`: non-ASCII characters in the path, query and fragment are UTF-8 percent-encoded, every ASCII character including existing `%XX` escapes is kept, a non-ASCII hostname is IDNA-encoded; callers still store the URL as given), sends `User-Agent: ideology-app/0.1 (+manifesto fetch)`, uses a 60 s timeout, rejects a `Content-Length` over `max_bytes`, reads in 1 MiB chunks up to `max_bytes`, and raises `FetchError(reason)` (≤ 500 chars): `HTTP <code>: <reason>` (the `HTTPError` is closed), `could not fetch URL: <detail>` (also for any `ValueError` such as `UnicodeError` or `http.client.InvalidURL`, so no urllib/http.client error escapes), `response is empty`, `response is too large (more than N bytes)`. No retries.
- `ideology_app.source_documents`: `add_uploaded_document(session, party_id, file_path, files_dir)` validates (Party exists, regular file, 0 < size ≤ 50 MiB, starts with `%PDF-`), inserts the row (`registered`; duplicate party+hash → `DuplicateError`), then `_store_and_parse` stores the file (`fetched`) and extracts pages (`parsed` + page rows, or `failed` + `failure_reason`). `add_url_document(session, party_id, url, files_dir, fetch=None)` checks the Party and the URL (absolute http/https with a host, no credentials, whitespace or control characters, ≤ 2048 chars; `invalid URL …` otherwise) before fetching, downloads once (cap `MAX_UPLOAD_BYTES`), and on a fetch error or a body not starting with `%PDF-` returns a `failed` row with `source_url` and `failure_reason` but no hash or file; otherwise it inserts the row with `source_url` and `original_filename` (percent-decoded last path segment) and runs the same `_store_and_parse`. Rows are never re-fetched. `list_documents`, `get_document`. Reuses the `elections` error classes.
- Migrations: Alembic in `src/ideology_app/migrations/` (`script_location = ideology_app:migrations` in code; root `alembic.ini` for developer commands). `env.py` reads the URL from the config or `database_url()`, supports offline `--sql`, uses `render_as_batch=True`, and disposes its engine.
- A CHECK added to an existing table is not detected by autogenerate; write it by hand inside `op.batch_alter_table` (as `0003` does).
- Add a migration: change `models.py`, then `DATABASE_URL=sqlite:///<scratch>/gen.db .venv/bin/alembic -c alembic.ini upgrade head` and `... revision --autogenerate --rev-id 000N -m "..."`, review the file by hand (see `CONSTRAINTS.md`), and check `... alembic -c alembic.ini check` reports no drift. `tests/test_migrations.py` checks upgrade/downgrade, drift and the offline PostgreSQL render.

## LLM Providers

- Package `src/ideology_app/llm/`: `base.py` (`LLMRequest[T]` with `task`, `system`, `prompt`, `schema` (a pydantic model), `max_tokens=4096`; `LLMResult[T]` with `output`, `provider`, `model`, `input_tokens`, `output_tokens`; the `LLMProvider` protocol with `name`, `model`, `generate(request) -> LLMResult`; errors `LLMError` > `LLMConfigError` (also a `config.ConfigError`), `LLMOutputError`, `LLMProviderError`), `fake.py` (`FakeProvider`), `anthropic_provider.py` (`AnthropicProvider`), `__init__.py` (re-exports, `PROVIDERS` registry, `build_provider`).
- Selection: `build_provider(llm_settings())`. `PROVIDERS` / `build_provider` is the only place that branches on the provider name. Callers depend on the `LLMProvider` protocol, never on a concrete class.
- Configuration (`ideology_app.config`): `LLM_PROVIDER` (`anthropic` default, or `fake`), `LLM_MODEL` (default per provider from `DEFAULT_MODELS`: `anthropic` -> `claude-sonnet-5-5`, `fake` -> `fake-model`), `GENERATION_MODE` (`GenerationMode.PRECOMPUTED` default, or `LIVE`; parsed only, no behaviour yet). Values are trimmed, case-insensitive, and blank means unset. Invalid values raise `ConfigError` (a `ValueError`) listing the supported values. `ANTHROPIC_API_KEY` is read only by `AnthropicProvider`, lazily on the first `generate`.
- `FakeProvider(responses, model="fake-model")`: canned responses keyed by `task` (dict, schema instance, or callable `(request) -> dict | model`), validated against the schema; records `calls`; deterministic word-count token numbers. Unknown task -> `LLMError`; schema mismatch -> `LLMOutputError`.
- `AnthropicProvider(model, *, client=None, api_key=None, max_retries=2, timeout=120.0)`: `client.messages.parse(..., output_format=request.schema)` (SDK structured output, `output_config.format.type == "json_schema"`). Maps `pydantic.ValidationError`, refusals and missing parsed output to `LLMOutputError`, and `anthropic.APIError` to `LLMProviderError` (class name and HTTP status only). Closes only a client it created (`close()` / `with`). Retries are the SDK's `max_retries`.
- Dependency direction: `config` -> `llm`. `config` never imports `llm`. `pipeline` imports only `llm.base`; `cli` imports `build_provider` (in `cli._provider`).
- Add a provider: write `src/ideology_app/llm/<name>_provider.py` implementing the protocol, add one entry to `PROVIDERS` and one to `config.DEFAULT_MODELS`.
- Tests: `tests/test_llm.py` (config, registry, fake) and `tests/test_llm_anthropic.py` (adapter through an injected `anthropic.Anthropic` with an `httpx2.MockTransport` `http_client`). Each has an autouse guard that unsets the LLM env vars and blocks `socket.socket.connect` / `socket.create_connection`.

## Pipeline

- Package `src/ideology_app/pipeline/`: `prompts.py` (topics, schemas, versioned prompts), `generation.py` (chunking and Statement LLM calls, no database), `positions.py` (Party Position LLM calls, no database), `runs.py` (Pipeline Run service), `__init__.py` (re-exports). Dependency direction: `models` / `elections` (errors) / `llm.base` → `pipeline` → `cli`. It never imports a concrete provider; the provider is injected.
- `prompts.py`: `Topic` (a `Literal` of 18 slugs, `economy` … `infrastructure_transport`) and `TOPICS`; schemas `StatementDraft` (`text` 1..300 chars with a non-space character, `topic: Topic`), `CandidateList` (`candidates`, ≤ 12), `StatementSet` (`statements`, 1..60); `PromptSpec(task, version, system, template, schema, max_tokens)` with `STATEMENT_CANDIDATES` (`v1`, 4096 tokens, field `{chunk}`) and `GENERATE_STATEMENTS` (`v1`, 8192 tokens, fields `{candidates}`, `{count}`); `POSITION_FINDINGS` (`position_findings`, `v1`, 4096 tokens, fields `{statements}`, `{chunk}`; schema `FindingList(findings ≤ 60 of Finding(statement ≥ 1, value −2..+2, quote 1..500 chars with a non-space, page ≥ 1))`) and `PARTY_POSITIONS` (`party_positions`, `v1`, 8192 tokens, fields `{statements}`, `{candidates}`; schema `PositionList(positions ≤ 60 of PositionChoice(statement ≥ 1, value −2..+2, evidence ≥ 1))`); `PROMPT_VERSIONS` (task → version for all four tasks, recorded on every run); `TARGET_STATEMENT_COUNT = 30`. Prompts are in Spanish and state the single-proposition, neutral-wording, 5-point-scale and topic rules; the reduce prompt adds topic spread (no topic over about a quarter), no near-duplicates and the target count.
- `generation.py`: `CHUNK_MAX_CHARS = 40_000`, `MAX_LLM_CALLS_PER_RUN = 200`. `build_document_chunks(documents)` returns `Chunk(party_id, document_id, text)`; `build_chunks(documents)` is its texts (pure; `DocumentPages(party_id, document_id, pages, source_url=None, role=main)`): documents ordered by Party id then document id, pages by number; each page rendered as `[página N]\n<text as stored>`, pages joined by a blank line; a chunk holds whole consecutive pages of one document and is at most the limit (a page over the limit is cut into consecutive slices, each under its marker); whitespace-only pages are left out. `generate_statements(provider, chunks, usage)`: map (one `statement_candidates` call per chunk), then reduce (candidates with exact duplicates removed, sorted by (topic, text), one `generate_statements` call). `Usage` (calls, input/output tokens) is updated after each successful call. `GenerationError` for `too many chunks: <n> (limit 199)` (before any call) and `no statement candidates were found in the source documents`; `LLMError` propagates.
- `positions.py`: `MAX_POSITION_CALLS_PER_RUN = 300`; `plan_position_calls(documents)` = chunks + Parties with at least one chunk (an upper bound). `extract_positions(provider, statements, documents, party_ids, usage)`: Parties in id order; each chunk of a Party's documents (main document first, then document id, then page; the same 40,000-character chunks) gets one `position_findings` call whose prompt lists the Statements as `[n] <text>` and then the chunk; findings become numbered candidates `C<k> [programa principal|programa adicional] [afirmación n] [valor v] [página p] «quote»`, and one `party_positions` call per Party picks one stance per Statement and the candidate it cites (any candidate for any Statement). No candidates → no reduce call. Returns exactly n `PositionResult(statement_number, value, document_id, quote, page, url)` per Party; omitted Statements and Parties without documents are `no stance`. `GenerationError` for `position_findings|party_positions referred to unknown statement <n>`, `party_positions repeated statement <n>` and `party_positions referred to unknown evidence candidate <k> (…)`; `LLMError` propagates. Quotes and pages are kept as returned (no Validation here). Coalition precedence is a prompt rule: the main (joint) manifesto wins on conflict.
- `runs.py`: `queue_run(session, election_id, *, llm_provider, llm_model, generation_mode)` (Election must exist and have a `parsed` Source Document; flushes a `queued` run; the caller commits). `execute_run(engine, run_id, provider) -> RunOutcome` commits at two points: (1) checks the run is `queued` and the provider's `name`/`model` equal the recorded ones (else `InvalidInputError`, nothing changed), records a `pipeline_run_source_documents` row per parsed document (each Party's lowest-id parsed document is `main`, the others `additional`), sets `running` + `started_at` and loads the parsed pages (with `source_url` and role) and the Election's Party ids as plain data; then, outside any transaction, checks the position call budget (`too many position extraction calls: <n> (limit 300)`, before any LLM call), generates the Statements and extracts the positions; (2) in one commit inserts a `candidate` `DatasetVersion`, its Statements at positions 1..n exactly as returned and n × Parties `PartyPosition` rows, and sets `validating`; or on `LLMError` / `GenerationError` sets `failed` with `str(exc)[:500]` and no Dataset Version; `KeyboardInterrupt` sets `failed` with `interrupted` and is re-raised; any other exception sets `failed` with `unexpected error: <ClassName>` and is re-raised. The source-document rows of a failed run remain. Both record usage and `generation_finished_at`. `RunOutcome` has `statement_count` and `position_count`. `list_runs(session, election_id)`, `get_dataset_version(session, id)`, `list_positions(session, dataset_version_id, party_id=None)` (ordered by Statement position then Party id; `NotFoundError` for an unknown version or a Party not in its Election). No update or delete path for Dataset Versions, Statements or Party Positions.
- The run stops at `validating`; Validation and publishing are later features. A hard kill or crash still leaves a run `running` (no recovery command). The CLI runs synchronously in both Generation Modes and only records the mode.
- Bump a prompt: edit `prompts.py`, change that prompt's `version` (e.g. `v2`), and replace its `(task, version)` entry in `FINGERPRINTS` in `tests/test_pipeline_prompts.py` with the fingerprint the failing test prints.
- Tests: `tests/pipeline_fixtures.py` (ORM seeding, default fake responses for all four tasks, `chunk_pages` / `candidate_lines` request parsers, `offline_guard`), `tests/test_pipeline_prompts.py`, `tests/test_pipeline_generation.py`, `tests/test_pipeline_positions.py`, `tests/test_pipeline_runs.py`, `tests/test_cli_pipeline.py`, each with the autouse env/socket guard.

## Client-side Matching

- Module: `src/ideology_app/static/js/match-score.js`, a pure ES module (named exports only, no imports, no browser or network globals). It implements the Matching Rule in `docs/build-brief.md` and is meant to run in the Voter's browser, so Answers never reach the server. Intended URL once a UI feature mounts `/static` (not mounted yet): `/static/js/match-score.js`, loaded from a `<script type="module">`.
- Exports: `SKIP = "skip"` (Answer value), `NO_STANCE = "no_stance"` (Party Position value), `IMPORTANT_WEIGHT = 2`, `LOW_COVERAGE_THRESHOLD = 5`, `statementAgreement(a, p)` (`1 - |a - p| / 4`), `computeMatchScore(answers, positions, options)` → `{ matchScore, sharedStatementCount, lowCoverage }`, `computeMatchScores(answers, parties, options)` → the same plus `partyId`, in input order (no sorting).
- Inputs: Answers `{ statementId, value: -2..2 | "skip", important?: boolean }`, Positions `{ statementId, value: -2..2 | "no_stance" }`, Parties `{ partyId, positions }`. `statementId` is matched by `String(statementId)`. `options.lowCoverageThreshold` is a positive integer.
- Zero shared Statements gives `matchScore: null` and `lowCoverage: true` (never `NaN`). A missing Answer or Position is excluded like skip / no stance. Invalid input throws `TypeError` (non-array, non-boolean `important`) or `RangeError` (bad value, duplicate `statementId`, bad threshold) naming the field and `statementId`.
- The root `package.json` is `{"private": true, "type": "module"}` only, so Node treats the `.js` files as ES modules without a warning. It has no dependencies and is never used for `npm install`.
- Tests: `tests/js/*.test.js` with `node:test` and `node:assert/strict` (Node >= 22, built in, no npm packages).

## Runtime Surface

- ASGI app: `ideology_app.main:app` (FastAPI).
- Endpoints: `GET /health` → `200 {"status": "ok"}`.
- Start locally: `.venv/bin/uvicorn ideology_app.main:app --reload`.
- Operator CLI: `.venv/bin/ideology` (`ideology_app.cli:main`, click; global `--database-url`, envvar `DATABASE_URL`): `db upgrade`, `election create --country --type --date --name`, `election list`, `party add --election --name --short-name`, `party list --election`, `source add --party --file PATH | --url URL` (exactly one, else usage error exit 2; prints `Created source document N: parsed (P pages)`; a `failed` document is committed, then reported as `Error: source document N failed: <reason>`, exit 1), `source list --party` (columns `id origin status pages content_hash filename url failure_reason`), `source text --document [--page]`, `pipeline run --election` (resolves the provider through `cli._provider()` = `build_provider(llm_settings())` and `GENERATION_MODE` before any write, so an invalid value exits 1 with no run row; queues and executes a run synchronously; prints `Pipeline run N: validating (dataset version D, S statements, P party positions)`; a `failed` run is committed, then reported as `Error: pipeline run N failed: <reason>`, exit 1; closes the provider if it has `close`), `pipeline list --election` (columns `id status provider model mode dataset_version statements llm_calls input_tokens output_tokens failure_reason`), `pipeline statements --dataset-version` (columns `position topic text`), `pipeline positions --dataset-version [--party]` (columns `statement party value document page url quote`, ordered by Statement position then Party id; `no stance` rows print `no_stance` and empty evidence cells; each whitespace run in the quote is shown as one space, display only; an unknown version or Party exits 1). Lists are tab-separated with a header (empty cells for nulls). Service errors exit 1 (`Error: …` on stderr), click usage errors exit 2, and `election`/`party`/`source`/`pipeline` commands on a database not migrated to head (Alembic revision equals the script head) exit 1 with `Database is not initialised; run "ideology db upgrade".`
- Test client: `fastapi.testclient.TestClient`, backed by `httpx2` (Starlette deprecates `httpx` for the test client).

## Verification Gate

- `./init.sh` runs from its own directory, creates `.venv` if missing (`${PYTHON:-python3} -m venv`), then runs ordered steps through `run_step <name> <function>`, which prints `==> <name>`, runs the step in a `( set -e; ... )` subshell outside any condition (bash ignores `set -e` inside `if`/`!`/`&&`/`||`), and exits 1 with `FAILED: <name> (exit N)` on failure. So any failing command in a multi-command step fails the gate.
- Current steps: `node` (Node.js >= 22 on `PATH`, `NODE_MIN_MAJOR`; fails before anything is installed), `install` (`pip install -e '.[dev]'`), `pytest`, `js-test` (`node --test tests/js/*.test.js`; fails if there are no test files, because `node --test` exits 0 when nothing matches). Pytest runs with `filterwarnings = ["error"]`, so warnings (including leaked-connection `ResourceWarning`s) fail the gate. Migration checks run inside pytest. `tests/test_init_script.py` checks `run_step` and `step_node` by extracting them from `init.sh`.
- To add a step, define a `step_<name>` function and add a `run_step` line after the existing ones. Steps are functions so their arguments are never word-split. Keep `init.sh` compatible with macOS `/bin/bash` 3.2 (under `set -u`, check an array's length before expanding `"${arr[@]}"`).
- `init.sh` never starts a server; it only prints the start command after all checks pass.
