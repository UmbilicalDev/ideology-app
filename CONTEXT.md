# Context

## Glossary

> **Model generation.** *Legacy* rules describe Dataset Versions 1–5 (Election 1 = 2023: versions 1–3; Election 2 = 2026: versions 4–5) and the current national pipeline until `statements-from-proposals` and `constituency-selection-validation` replace it. **v2** rules describe the Dataset Versions that pipeline produces; the first real one comes from `e2e-2026-constituencies`. Older versions stay readable and are never rewritten. A Pipeline Run and its Dataset Version carry the marker `model_generation` (`legacy` or `v2`), set when the run is queued and copied into the Dataset Version at insert, never updated; Dataset Versions 1–5 read `legacy` (`statements-from-proposals`, S7). A term with no label applies to both.

### Election
A specific electoral call in one country (e.g. Spanish general election of 23 July 2023). The model supports many elections; the MVP loads only Spanish general elections.

### Constituency
One of the 52 circunscripciones of the Congreso de los Diputados (50 provinces, Ceuta, Melilla). Congreso only, no Senado. It is reference data with an INE code (`01`..`52`, Ceuta `51`, Melilla `52`) and a Spanish name (the INE name with an inverted article moved to the front, e.g. `A Coruña`), seeded by a migration and changed only by migration (v2, `constituencies-and-candidatures`; `ideology constituency list`). A Voter picks it first; the Questionnaire, the results and the Comparador follow it. In a Dataset Version a Constituency is available, or unavailable with a reason (e.g. lack of manifestos): an unavailable Constituency is disabled in the list and the map with that reason, and it never fails a run. *Legacy (Dataset Versions 1–5):* there are no Constituencies; everything is national.

### Party
**v2:** a candidature with its own name and logo that runs in a list of Constituencies (a regional coalition is its own Party). The Operator enters which Party runs where from the proclaimed candidatures (BOE, source recorded); this is never generated by AI (`constituencies-and-candidatures`). Inclusion rule: every candidature with a manifesto of enough content; the others are Excluded Parties. The Operator declares the candidatures in a format-2 `election.toml` (`[[parties]]` with `constituencies`), imported by `ideology data import`. Candidatures that share a manifesto under different names stay separate Parties; the manifesto is listed once with every Party it applies to (see Source Document). *Legacy-only Party* (v2): a Party row of an Election that a format-2 manifest does not list (e.g. a 2026 Party of Dataset Versions 4–5 that is not a v2 candidature); it keeps its row, documents and Positions, has no candidatures, and v2 features ignore it. A format-2 manifest reuses an existing Party row only when both its short name and name are equal; Party rows are never renamed or deleted (D2, default for team review).

*Legacy (Dataset Versions 1–5):* a ballot ticket in an Election: a single party or an electoral coalition (e.g. Sumar), exactly as it appeared on the ballot, national scope. Splits after the election are ignored for that Election. Inclusion rule: a national Party set chosen per Election by user decision (see `docs/risks-and-open-questions.md`): for 2023 (Dataset Versions 1–3), the tickets with seats from the 2023 result, with CCa and UPN not included; for 2026 (Dataset Versions 4–5), the tickets with a seat in the 40dB/EL PAÍS projection of 19 Nov 2026 and an official manifesto, plus Podemos and SALF, with CC and EAJ-PNV not included.

A Party may have a logo: a local PNG, WebP or SVG image stored with the Party (never a remote URL), imported from its Source Text Bundle or set by the Operator; a Party without one is valid. The logo is a Party attribute, not part of a Dataset Version.

### Excluded Party
**v2:** a Party with no manifesto, whose manifesto the Operator discarded at review (no text layer, not a manifesto, clearly incomplete), or with fewer than N validated Proposals (configurable, default 30; checked automatically after phase 3). N counts per Party, summing the validated Proposals of all its Source Documents: a Party is Excluded only if that total is below N (user decision 2026-11-24; `proposal-extraction`, `ingestion-ledger`). It is recorded with its reason (`no_manifesto`, `discarded_at_review`, `too_few_proposals`) in the Ingestion Ledger; a no-manifesto exclusion is an explicit Operator decision, and a Party only partly discarded at review is not Excluded (`ingestion-ledger`). It appears only in the results note of each Constituency where it runs, never in the ranking and never with a score.

*Legacy (Dataset Versions 1–5):* Parties were never excluded by the pipeline (a Party below coverage failed the run). The 2026 note on the Parties not included in that Election (user decision) is hard-coded in the web client until `results-by-constituency` reads it from the Dataset Version.

### Source Document
A document that states a Party's positions for an Election, normally its election manifesto (programa electoral). Registered by an Operator as an uploaded file or a URL, or imported from a Source Text Bundle. A URL document whose content changed is replaced by a new one, and so is a bundle document whose committed file changed; the old one stays for the Evidence of older Dataset Versions.

**v2:** it declares the Parties and the Constituencies it applies to (`[[documents]]` in a format-2 `election.toml`). A Source Document listed for several Parties (e.g. a national manifesto shared by the national Party and its provincial coalition) is stored as one Source Document row per Party, sharing the file and its content hash; each row's scope is the Constituencies the document declares, or every Constituency of that Party, intersected with that Party's Constituencies (D1, `constituencies-and-candidatures`; default for team review). A coalition's joint manifesto takes precedence over a member's: the manifest marks it with `joint_for = ["UPN-PP"]` on its `[[documents]]` entry, naming the listed Parties for which it is the coalition's own joint manifesto (a shared national file listed for both the national Party and the coalition is joint for neither). Other contradictions between documents of the same Party and Constituency are flagged and decided by the Operator (see Operator; `proposal-conflicts`). At phase 2 the Operator reviews it and may discard it with a reason.

### Source Text Bundle
The committed text of an Election's manifestos plus its manifest: `data/elections/<slug>/` (slug `es-general-2023-07-23`) with `election.toml` and one Markdown Source Text file per Party, written by `ideology source extract` from the PDF and never edited. It is imported into any database with `ideology data import`, so every machine reads the same source text without passing PDFs or databases around. No PDF is committed. It may also hold the Parties' logo files in an optional `logos/` directory, each declared by its Party in `election.toml`.

### Ingestion Ledger
**v2:** the committed per-Election file next to the Source Text Bundle (`ingestion-ledger`). It records, per Party, the phase reached or the Excluded reason, and the Operator's conflict decisions (`proposal-conflicts`). Phases: 1 candidatures per Constituency, 2 provide and review manifestos, 3 extract Proposals, 4 generate Statements. Phase 4 starts only when every Party is Extracted or Excluded and no conflict is pending. The guided procedure that reads it is `ingestion-guide`. Per Party it writes the phase `candidature_declared`, `manifesto_reviewed`, `proposals_extracted` or `excluded` with the reason `no_manifesto`, `discarded_at_review` or `too_few_proposals`; per document, the review (`kept`, or `discarded` with `no_text_layer`, `not_a_manifesto` or `incomplete`) and the validated Proposal count. Review is per document: a Party is Excluded at review only when every document it lists is discarded; otherwise its kept documents go on and only they count toward N (L4, default for team review). Written only by `ideology ingestion` commands, plus `ideology conflicts` (below).

**Conflict** (`proposal-conflicts`): two kept documents of one Party whose scopes intersect form an *overlap*, listed in the ledger with its Constituencies. `ideology conflicts detect` asks the LLM, one topic-catalog category at a time, which Proposals of one contradict Proposals of the other (only pairs that cannot both hold), and records the check. Status: `unchecked` → `no_contradiction`, or flagged → `joint_manifesto` (exactly one of the two is the Party's joint manifesto, which prevails automatically) or `pending` → `decided` (the Operator names the prevailing document, with a reason, through `ideology conflicts decide`). Only the losing document's contradicting Proposals are set aside, only for that Party and only in the overlap Constituencies (C2, default for team review); every other Proposal of both documents still counts, and Proposals are never edited. A content change of either document clears the check and the decision.

### Proposal
**v2:** a verbatim concrete measure or commitment from a Source Document (a point or paragraph; diagnosis or context only when relevant), with its page, one or more main categories from the topic catalog (`topic-catalog`, usually one) and free secondary tags. It is kept only if its text is on the cited page (the same normalised match as Evidence). It is extracted once per document, reused while the document is unchanged, and extracted incrementally over several runs (`proposal-extraction`). It is never edited. "Propuesta" in Spanish copy. Proposals belong to the document content (its `content_hash`), not to a Dataset Version or a Party's row: one extraction serves every Party that shares the file and the same bytes in any Election, and the items dropped by the check are recorded with their reason (`proposal-extraction`).

### Statement
A short, neutral proposition the user rates (e.g. "The minimum wage should rise faster than inflation"), generated by the AI.

**v2:** built from a group of similar Proposals, carries one category from the topic catalog (its group's main category, stored as its topic), and may be valid in some Constituencies only. Its source Proposals (the group it was drafted from, in citation order) are recorded; they may go in either direction, so a Party that owns a source Proposal can still have no stance on it (`statements-from-proposals`, S1, S12). A Statement in a Dataset Version is never edited; a Statement Rewording yields a new Dataset Version.

*Legacy (Dataset Versions 1–5):* generated from the Party-balanced Agenda of the Source Documents, with a topic tag.

### Statement Rewording
**v2:** an Operator's rewording of a confusing Statement without changing its meaning (`statement-rewording`). It is an input file of a new run, so it produces a new Dataset Version and published versions stay untouched. The AI text, the new text and the reason are stored. Party Positions and Evidence stay unchanged. An automatic LLM equivalence check rejects a rewording that changes the meaning; a rejected rewording does not fail the run: the Statement keeps its AI text and the pipeline report shows the rejected rewording (user decision 2026-11-24). Voters see only the final text, with no marker. `/metodologia` says the authors may reword AI-generated Statements judged confusing.

### Context Note
A short neutral explanation of the law, plan, institution or term a Statement names, generated by the AI with the Statement and checked by Validation; never hand-written; absent on Dataset Versions created before it existed.

### Questionnaire
**v2:** the Statements valid in one Constituency of one Dataset Version (the Voter picks the Constituency first), in that Constituency's priority order (`constituency-selection-validation`), so a shorter questionnaire is a prefix (see Questionnaire Length).

*Legacy (Dataset Versions 1–5):* the ordered set of Statements for one Election in one Dataset Version, one national order. Since `pipeline-statement-priority-tiers` the order is the priority order of Statement Selection (position 1 = most Parties in favour or against).

### Questionnaire Length
**v2:** 20, 30, 40 and 50, each offered only when the Constituency has that many valid Statements, or `Todas (N)`, offered only when it has fewer than 20 (user decision 2026-11-24). Each is a prefix of the priority order. After the chosen length the Voter may pick `Contestar 5 más`, `Contestar 10 más` (or the exact number left) or `Ver resultado`, repeatedly, so any count may be answered (`questionnaire-length-and-context`).

*Legacy (Dataset Versions 1–5):* a length a Dataset Version offers (e.g. 15, 30 and its full count, 35 to 40); a questionnaire of length N is its first N Statements in priority order. Coverage and topic spread are validated on every offered length. Versions created before `pipeline-statement-priority-tiers` offer only their full length.

### Answer
The user's response to a Statement, one of three options: `De acuerdo` (agree, +1), `En desacuerdo` (disagree, −1) or `Neutral / No lo sé` (neutral). Neutral leaves the Statement without a value: it does not count toward the Match Score. There is no separate `skip` (removed 2026-11-21, `three-option-scale`). An Answer may be marked Important.

### Important
A flag the user sets on an Answer, before answering; that Statement counts double in the Match Score (weight 2). A Neutral Answer drops the flag, because it would not count.

**v2:** no cap; any Statement may be Important (`important-unlimited`).

*Legacy rule (round 1):* at most a third of the questionnaire's Statements (rounded up) can be Important, which the web client enforces until `important-unlimited` lands.

### Party Position
The AI-extracted stance of a Party on a Statement, stored on a 5-point scale (−2..+2), or `no stance`. Every non-`no stance` Party Position carries Evidence. For matching it is read by side: −2/−1 against, +1/+2 in favour; 0 (neutral) is excluded like `no stance`. Validation's coverage and separation and Statement Selection read it the same way (a Party "takes a side" only at ±1/±2).

**v2:** the Evidence is one or more of that Party's Proposals. A Party may be against a Statement only when one of its Proposals backs that. A Party with no related Proposal has no stance (`statements-from-proposals`). There is one Party Position per Party and Statement in a Dataset Version; a Position applies in a Constituency only when one of its Evidence Proposals counts there for that Party, and otherwise it reads as `no stance` there (S5, applied by `constituency-selection-validation`).

### No Stance
The Party's Source Documents do not address the Statement (v2: none of its Proposals relates to it). The Statement is excluded from that Party's Match Score and shown as "no stance in the manifesto".

### Evidence
What justifies a Party Position. Visible to the user.

**v2:** one or more of the Party's Proposals (verbatim text, page, Source Document locator), ranked in citation order. Each Evidence Proposal records the Constituencies where it counts for that Party, frozen in the Dataset Version. Rank 1 is also stored as the Position's single quote (the Proposal text, its page, its Source Document and URL), so the legacy readers and the `evidence_quotes` check work unchanged (S6).

*Legacy (Dataset Versions 1–5):* a verbatim quote from a Source Document plus its locator (page and/or URL).

### Dataset Version
An immutable snapshot of one Election's Questionnaire and Party Positions produced by one Pipeline Run. Share Links reference a Dataset Version. **v2:** it also fixes, per Constituency, its availability (or the reason it is unavailable), its ordered Statements, its offered lengths and its Excluded Parties with their reasons (`constituency-selection-validation`).

### Pipeline Run
One execution of the AI process, followed by Validation.

**v2:** the phase 4 run. It reads the Extracted Proposals, the conflict decisions and any rewording file, builds Statements and Party Positions, then applies the per-Constituency Statement Selection and Validation. Phase 3 extraction is not a Pipeline Run: it is recorded per document content in its own tables (`proposal-extraction`).

*Legacy (Dataset Versions 1–5):* Party-balanced Agenda → Statement Pool → Party Positions → Statement Selection of the Questionnaire.

### Party-balanced Agenda
*Legacy pipeline term.* The candidates given to Statement generation, the same number from every Party whatever its manifesto length. A Party with fewer candidates gives all it has; nothing is invented for it. It is chosen by deterministic code and recorded on the Pipeline Run.

### Statement Pool
The list of Statements a Pipeline Run positions every Party on, before the Questionnaire is chosen from it. **v2:** every Statement drafted from the counted Proposals, after a deterministic, party-blind filter that leaves out Statements whose Context Note would fail Validation and exact duplicates; there is no bound, the target is 200 or more (about one Statement per 12 Proposals), and a smaller pool only warns (`statements-from-proposals`, S3). *Legacy:* 100 to 140 by default since `pipeline-statement-priority-tiers`, generated from the Party-balanced Agenda.

### Anchor
*Legacy pipeline term.* The Statements of the Election's Published Dataset Version, given to Statement generation to be rewritten; they stay only if their rewritten Statement passes Statement Selection. **v2:** none; a v2 run never uses Anchors (`statements-from-proposals`, S8).

### Statement Selection
**v2:** deterministic and Party-identical; per Constituency, a Statement is valid when, among the Parties running there, at least one is in favour and one against. The priority order is computed per Constituency, and a Constituency below the minimums is unavailable with its reason. The minimums and the topic spread are open, owned by `constituency-selection-validation`; see `docs/risks-and-open-questions.md`.

*Legacy (Dataset Versions 1–5):* the deterministic choice (no AI, no randomness, every Party weighted the same) of the Questionnaire's Statements from the Statement Pool, in priority order: Statements whose Context Note would fail Validation, duplicates, Statements without at least one Party in favour and one against, and Statements fewer than 3 Parties (configurable) take a side on are left out; the rest are ranked by the number of Parties with a side (ties: the more even split, then pool order); a topic cap per offered length defers a Statement to the first position where its topic fits; and the count is the largest in the configured range (35 to 40) whose full set meets the coverage threshold. Earlier runs (selection v1/v2) maximised the worst-covered Party's coverage and kept pool order. It is recorded on the Pipeline Run and shown by `ideology pipeline report`.

A Statement in a Dataset Version is never edited; the only change to a Statement's text is a Statement Rewording, which goes through a new run.

### Validation
Automatic checks a Pipeline Run's output must pass before it is published; the only way to publish. **v2:** some checks are per Constituency, where a failure makes that Constituency unavailable rather than failing the run. A v2 run is checked with `evidence_quotes`, `evidence_proposals` (every sided Position has Evidence Proposals of that Party, on their page, with Constituencies, and rank 1 mirrored), `statement_sources` (every Statement has source Proposals from the run's documents), `statement_uniqueness` and `context_note`; a passed v2 run stays `candidate` until `constituency-selection-validation` adds the per-Constituency checks and turns publishing on (`statements-from-proposals`, S9). There is no human review. The only Operator inputs are recorded conflict decisions and Statement Rewordings, which go through a run and Validation.

### Published
State of the Dataset Version currently served to users for an Election. At most one per Election at a time (none before the first passing run). Set automatically when a Pipeline Run passes Validation; the version it replaces becomes superseded.

### Match Score
Percentage affinity between a user's Answers and a Party's Positions: the weighted share of compared Statements where both are on the same side. **v2:** computed only for the non-excluded Parties running in the Voter's Constituency.

**Coincidence**: a compared Statement (sided Answer and sided Party Position) where the Voter and the Party are on the same side. The ranking shows `N de M coincidencias`: M Statements compared with that Party, N coincidences.

### Share Link
A URL that encodes the Dataset Version and the user's Answers so the result can be reopened or shared. Never stored on the server.

**v2:** the fragment carries the Dataset Version, the Constituency and the Answers with their Important flags for however many Statements were answered (`share-link-v3`, layout `v3`). Every older layout (layout `v1`, layout `v2`, so every link to Dataset Versions 1–5) opens the outdated-version notice.

### Operator
The person who runs the system. **v2** duties: declare candidatures per Constituency, provide and review manifestos (discard with a reason), decide flagged contradictions (with a reason), reword Statements through a rewording file, and trigger runs, guided by `ingestion-guide`. The Operator never edits Proposals or Party Positions. *Legacy (Dataset Versions 1–5):* registers Elections, Parties and Source Documents, and triggers Pipeline Runs.

An Operator also reads and moderates Feedback Messages on the admin page (`/admin`), signed in with their own account (username and password). Voters never have an account.

### Feedback Message
An anonymous message a Voter sends about the tool (from the Landing or the results). An Operator may mark it as reviewed (and undo that) or delete it. It is never Answers and carries none.

### Generation Mode
Configuration that decides when Pipeline Runs happen: `precomputed` (the Operator triggers runs; static data is served) or `live` (a Pipeline Run is queued automatically when a Source Document is added or its content changes, and executed by the Operator's queue command, `ideology pipeline run-queued`). Neither mode generates per user.

## Rejected / Ambiguous Terms

### Question
Use `Statement`. Reason: users rate propositions, they do not answer open questions.

### Program / Manifesto
Use `Source Document`. Reason: a manifesto is the usual case, but the concept covers any registered source.

### Result
Use `Match Score` for a single party and "results" only for the full ranking screen.

### Propuesta
Means Proposal, not Statement (the UI calls Statements `afirmaciones`).

### Provincia / circunscripción / distrito
Use `Constituency`.

### Candidatura / coalición
Use `Party`. Reason: each candidature is one Party.

### Edit (a Statement)
Use `Statement Rewording`. Nothing else is ever edited.

### Topic / tema / categoría
A main category of the topic catalog (`topic-catalog`): 18 stable keys (`housing`, `economy`, …), each with a Spanish name (Vivienda, Economía, …), in citizen-priority order: how often citizens name the issue as one of Spain's main problems in CIS estudio 3587, Pregunta 6R (November 2026; source and rule in `docs/technical-discovery.md`). Keys are never renamed or removed while a Dataset Version uses them; legacy Statements (Dataset Versions 1–5) use the same keys. Secondary tags are free and are not topics.

### Excluded vs left out
An Excluded Party is never scored; a Statement left out by Statement Selection is a different thing. "Left out" is used only for Statements; a Party the Operator did not add to a legacy Election is "not included".
